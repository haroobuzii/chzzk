# 녹화방송: 치지직 만들기 ② 휴대폰 라이브 송출

로그인 없이 방송을 올리고 시청하는 웹 서비스다. 화면과 서버 모두 Rust [Dioxus](https://dioxuslabs.com) 0.7 fullstack 크레이트 하나로 만들었다.

- **1단계 (녹화 방송)**: 누구나 제목과 MP4 영상을 올려 방송을 등록하고, 목록에서 골라 상세 화면에서 재생한다.
- **2단계 (라이브 방송)**: 누구나 휴대폰 브라우저에서 카메라·마이크로 라이브 방송을 송출하고, 다른 사람은 컴퓨터나 휴대폰 브라우저에서 1초 안팎의 지연으로 시청한다.

"치지직 만들기" 과제 4단계 중 2단계이며, 1단계 기능을 그대로 유지하며 확장했다. 화면에 보이는 서비스 이름은 "녹화방송"이고, 실제 치지직의 로고·이름·색은 쓰지 않는다.

용어(방송, 녹화 방송, 라이브 방송, 방송 상태, 송출, 송출 키, 시청, 방송 번호)는 [GLOSSARY.md](GLOSSARY.md)를 따른다.

## 2단계 구현 범위

| 기능 | 내용 |
|---|---|
| 머리글 | "라이브 시작"(`/live/new`)과 "녹화 올리기"(`/new`) 두 버튼. 휴대폰 폭에서도 한 줄에 놓인다. |
| 송출 화면 (`/live/new`) | 제목을 넣고, 카메라 미리보기(기본 후면 카메라, 미리보기 소리는 꺼 둠)를 본 뒤 "방송 시작"을 누른다. 연결 중에는 "연결하는 중…"이 보이고 버튼이 잠긴다. 송출이 시작되면 빨간 LIVE 표시와 시청 주소(복사 버튼)가 나온다. |
| 카메라 전환 | 방송 전과 방송 중 모두 전면·후면 카메라를 바꿀 수 있다. 방송 중에는 연결을 끊지 않고 보내는 영상만 바꿔 끼운다. |
| 송출 종료 | "방송 종료"를 누르면 송출이 멈추고, 방송 상태가 종료가 되고, 카메라와 마이크가 꺼진다. |
| 자동 종료 | 송출 화면을 닫거나, 와이파이가 끊기거나, 화면이 잠겨 영상이 끊기면 서버가 몇 초 안에 알아채 방송을 종료로 바꾼다. 송출 화면을 떠날 때도 종료 요청을 한 번 보낸다. |
| 화면 꺼짐 막기 | 송출 중에는 화면이 저절로 꺼지지 않게 한다(Screen Wake Lock). 지원하지 않는 브라우저에서는 "송출 중에는 화면을 켜 두세요"를 보여 준다. |
| 안내 문구 | 카메라·마이크 권한 거절, HTTPS가 아닌 주소, 카메라 없음·사용 중, 송출 연결 실패(같은 와이파이인지 확인하라는 안내 포함)를 각각 한국어로 알려 준다. |
| 송출 키 | 라이브 방송을 시작한 화면만 송출 키를 받는다. 키가 있어야 송출 연결과 종료를 할 수 있으므로, 다른 사람이 내 방송을 끄거나 다른 영상을 끼워 보내지 못한다. 키는 송출 화면의 메모리에만 두고, DB에는 SHA-256 해시만 저장한다([ADR 0005](docs/adr/0005-stream-key-instead-of-login.md)). |
| 방송 상태 | 준비 → 방송 중 → 종료 순서로만 바뀌고 되돌아가지 않는다. 시작했지만 30초 안에 영상이 들어오지 않은 방송은 버려지며 화면 어디에도 보이지 않는다. |
| 목록 (`/`) | 방송 중인 방송이 있으면 맨 위에 "지금 라이브" 칸이 나온다. 그 아래 녹화·라이브 방송이 함께 최신순으로 나온다. 카드마다 녹화 / 빨간 LIVE / 종료 표시가 붙는다. 5초마다 저절로 갱신된다. |
| 시청 (`/broadcasts/번호`) | 녹화 방송과 같은 주소 모양이다. 방송 중이면 실시간 영상이 소리 꺼진 채 자동 재생되고, "소리 켜기" 버튼으로 소리를 켠다. 방송이 끝나면 몇 초 안에 "방송이 종료되었습니다"가 나온다. |
| 종료된 라이브 방송 | 제목, 시작 시각, 방송한 시간(예: 12분 34초)을 보여 준다. 다시 볼 수는 없다. 준비 중이거나 버려진 방송 주소는 "방송을 찾을 수 없습니다"(404)다. |
| 서버 재시작 | 라이브 방송 기록(제목, 상태, 시작·종료 시각)은 DB에 남는다. 서버가 꺼진 동안 끝난 방송은 서버가 켜질 때 바로 종료로 바뀐다. |

### 2단계 범위 밖

- 로그인·인가, 방송 소유자(3단계). 송출 키는 로그인이 아니라 방송 하나에만 쓰는 열쇠다.
- 댓글(3단계), 도네이션(4단계)
- 라이브 다시 보기(녹화 저장), 썸네일, 시청자 수, 채팅
- LTE·5G 등 컴퓨터와 다른 네트워크에서의 송출, TURN 서버. 휴대폰과 컴퓨터는 같은 와이파이에 있어야 한다([ADR 0004](docs/adr/0004-live-via-mediamtx-webrtc.md)).
- 화질 선택, 송출 중 제목 바꾸기, 방송 수정·삭제([ADR 0002](docs/adr/0002-no-edit-or-delete-without-auth.md))
- 실제 서버 배포. 내 컴퓨터와 Cloudflare 무료 터널까지만 한다.
- 실시간 알림 장치(WebSocket 등). 목록과 시청 화면은 5초마다 서버에 다시 묻는다.

## 1단계 구현 범위 (그대로 유지)

| 기능 | 내용 |
|---|---|
| 방송 등록 | `/new`에서 제목과 MP4 파일을 골라 등록한다. 업로드 진행률(%)이 보이고, 업로드 중에는 버튼이 잠긴다. 등록이 끝나면 새 방송의 상세 화면으로 간다. |
| 등록 규칙 | 제목은 앞뒤 공백을 지운 뒤 1~100자(문자 수)이고, 같은 제목도 된다. 파일은 확장자 `.mp4`와 파일 앞부분의 `ftyp` 표시로 MP4인지 본다. 최대 크기는 2 GiB(설정 가능)다. 어기면 한국어 이유를 보여 준다. |
| 원자적 등록 | 업로드가 끝까지 성공해야만 방송이 생긴다. 거절되거나 중간에 끊긴 등록은 방송 정보도, 영상 파일도 남기지 않는다. |
| 방송 목록 (`/`) | 최신 등록순 카드 격자. 카드에는 썸네일 자리(회색 칸), 제목, 등록 시각(한국 시간)이 있다. 방송이 없으면 "아직 방송이 없습니다"와 등록 버튼을 보여 준다. |
| 상세 화면 (`/broadcasts/번호`) | 영상 재생기, 제목, 등록 시각, 목록으로 돌아가는 링크. 영상은 원본 그대로 Range 요청으로 받으므로 끝까지 내려받지 않고 건너뛸 수 있다. |
| 없는 방송 | 없는 번호, `0`, `01`, `abc` 같은 주소나 정해지지 않은 주소는 404와 "방송을 찾을 수 없습니다"를 보여 준다. |
| 영속 저장 | 방송 정보는 PostgreSQL에, 영상은 보관 폴더(`DATA_DIR`)에 저장한다. 서버를 다시 켜도 그대로 조회된다. |
| 로그인 없음 | 등록·조회 화면과 서버 기능 모두 로그인 없이 쓴다. |

라이브 방송의 제목 규칙도 녹화 방송과 같다. 1단계에서 저장한 방송은 2단계로 바꾼 뒤 녹화 방송으로 그대로 조회된다.

### 1단계 범위 밖

- 인증·인가, 방송 소유자, 방송 수정·삭제 (3단계). 인증이 없는데 수정·삭제를 열면 누구나 남의 방송을 바꿀 수 있어서 만들지 않았다([ADR 0002](docs/adr/0002-no-edit-or-delete-without-auth.md)).
- 라이브 송출 (2단계에서 구현), 댓글 (3단계), 도네이션 (4단계)
- 영상 변환(HLS 등)·화질 선택·코덱 검사([ADR 0001](docs/adr/0001-serve-original-mp4.md)), 썸네일 생성, 재생 시간 표시
- 목록 페이지네이션·검색, 업로드 이어 올리기, 도배 방지
- 실제 서버 배포와 HTTPS. 1단계는 내 컴퓨터에서 실행한다.

## 구성

### 1단계: 녹화 방송

```
브라우저 ──► Dioxus fullstack 서버 (Rust, 크레이트 하나)
              ├─ 화면: 목록 / 상세 / 등록 (서버에서 그린 뒤 WASM이 이어받음)
              ├─ 서버 함수: GET /api/broadcasts/list, GET /api/broadcasts/info?id=번호
              ├─ axum 라우트: POST /api/broadcasts (multipart 등록)
              │               GET  /api/broadcasts/{번호}/video (Range 지원 영상 전송)
              ├─► PostgreSQL: broadcasts 표 (방송 번호, 제목, 영상 키, 등록 시각)
              └─► 보관 폴더(DATA_DIR): videos/<번호>.mp4
```

### 2단계: 라이브 방송

휴대폰은 WebRTC로 미디어 서버 [MediaMTX](https://github.com/bluenviron/mediamtx)에 영상을 보내고(WHIP), 시청자는 MediaMTX에서 받는다(WHEP). 우리 서버는 라이브 방송의 정보, 방송 상태, 송출 키만 관리하고 영상은 다루지 않는다([ADR 0004](docs/adr/0004-live-via-mediamtx-webrtc.md)).

```
                         ┌──────────────────────── 내 컴퓨터 ─────────────────────────┐
 휴대폰 (송출)            │                                                             │
  화면·연결 요청 ─HTTPS─► Cloudflare 터널 ─► 우리 서버 (localhost:8080)                │
                         │                    ├─ 송출 키 확인 뒤 WHIP/WHEP 요청을 넘김 ─┐ │
 컴퓨터 브라우저 (시청)   │                    ├─ 상태 감시기: 2초마다 경로 목록 확인 ──┤ │
  http://localhost:8080 ─────────────────────►├─► PostgreSQL (localhost:5433)         │ │
                         │                    │                                      ▼ │
                         │                    │          MediaMTX (Docker)              │
                         │                    │           ├─ WHIP/WHEP: 127.0.0.1:8889 │
                         │                    │           ├─ 관리 API:  127.0.0.1:9997 │
  휴대폰 영상 ─────────── 같은 와이파이, UDP ─────────────►└─ 영상:     LAN_IP:8189/udp │
                         └────────────────────────────────────────────────────────────┘
```

- **터널**: 휴대폰 브라우저는 HTTPS 주소에서만 카메라를 쓰게 해 준다. 그래서 `cloudflared`로 `https://…trycloudflare.com` 주소를 만든다. 터널은 화면과 연결 요청만 나른다.
- **같은 와이파이**: 영상 자체는 터널을 지나지 않고, 휴대폰이 같은 와이파이 안의 컴퓨터(`LAN_IP`의 UDP 8189번)로 직접 보낸다. 그래서 휴대폰과 컴퓨터가 같은 와이파이에 있어야 한다. 손님용 와이파이처럼 기기끼리 막아 둔 망에서는 송출이 연결되지 않는다.
- **보안 경계**: MediaMTX의 HTTP 포트(8889, 9997)는 내 컴퓨터 안(127.0.0.1)에만 열린다. 휴대폰과 시청자는 반드시 우리 서버를 거쳐야 MediaMTX에 닿으므로, 송출 키 확인을 건너뛸 수 없다.
- **상태 감시기**: 서버가 켜지면 2초마다 MediaMTX의 "지금 영상이 들어오는 경로"(`live/<방송 번호>`) 목록과 DB를 맞춘다. 영상이 들어오면 방송 중, 사라지면 종료, 준비로 30초가 지나면 버려짐이 된다.

라이브 방송에 쓰는 HTTP 라우트는 아래와 같다. 실패 응답은 1단계와 같은 `{code, message}` JSON이다.

| 요청 | 하는 일 |
|---|---|
| `POST /api/live` | 제목(JSON `{title}`)을 받아 준비 상태의 라이브 방송을 만들고 201과 `{id, key}`(방송 번호, 송출 키)를 준다. |
| `POST /api/live/{번호}/whip` (+ 세션 `PATCH`·`DELETE`) | 송출 연결. `Authorization: Bearer <송출 키>`가 맞을 때만 MediaMTX에 넘긴다. 틀리면 401. |
| `POST /api/live/{번호}/whep` (+ 세션 `PATCH`·`DELETE`) | 시청 연결. 키 없이 쓰며, 방송 중일 때만 넘긴다. |
| `POST /api/live/{번호}/end` | 송출 키가 맞으면 204와 함께 종료한다. 이미 종료된 방송도 204다. |

### 파일 위치

| 위치 | 하는 일 |
|---|---|
| `src/main.rs` | 화면(목록, 상세, 등록, 404)과 서버 함수 |
| `src/routes.rs` | 등록 API(스트리밍 업로드, 검사, 원자적 저장)와 영상 전송 |
| `src/publisher.rs` | 송출 화면 `/live/new`(카메라, WHIP 송출, 카메라 전환, 화면 꺼짐 막기, 안내 문구) |
| `src/viewer.rs` | 라이브 시청 화면(WHEP 시청, 소리 켜기, 종료 안내) |
| `src/display.rs` | 카드 표시(녹화·LIVE·종료), 카드 시각, 방송한 시간 |
| `src/live/` | 라이브 방송 서버 쪽: 시작·종료와 WHIP 중계(`mod.rs`), 시청 중계(`watch.rs`), 저장소(`store.rs`), 송출 키(`key.rs`), MediaMTX 연결(`mediamtx.rs`), 상태 감시기(`status_sync.rs`) |
| `src/title.rs` | 제목 규칙 |
| `src/number.rs` | 주소의 방송 번호 읽기 |
| `src/db.rs` | 방송 정보 저장과 조회 |
| `src/videos.rs` | 영상 보관(임시 파일, 최종 위치로 옮기기) |
| `src/config.rs`, `src/server.rs` | 환경 변수 읽기, DB 접속, 라우터 조립, 상태 감시기 시작 |
| `migrations/` | 표 만들기 SQL. 서버가 켜질 때 자동으로 적용한다. |
| `docker-compose.yml` | PostgreSQL과 MediaMTX. MediaMTX 설정도 이 파일의 `configs.mediamtx`에 있으며, WebRTC와 관리 API만 켠다. |

설계 결정은 [docs/adr/](docs/adr/), 용어는 [GLOSSARY.md](GLOSSARY.md)에 있다.

## 실행 방법

필요한 것: Rust(rustup. 버전은 `rust-toolchain.toml`에 고정되어 있어 처음 빌드할 때 자동으로 설치된다), [Dioxus CLI](https://dioxuslabs.com/learn/0.7/getting_started) 0.7, Docker, 라이브 송출을 해 볼 때는 `cloudflared`와 휴대폰

1. 환경 변수 파일을 만든다. 들어 있는 값은 로컬 개발용 예시다.

   ```bash
   cp .env.example .env
   ```

2. `.env`의 `LAN_IP`를 이 컴퓨터의 와이파이 IP로 바꾼다. 휴대폰이 영상을 보낼 주소다.

   ```bash
   # macOS
   ipconfig getifaddr en0
   ```

   - 위 명령이 아무것도 출력하지 않으면 `en1`로 해 본다. 시스템 설정 → Wi-Fi → 연결된 와이파이의 "세부사항"에서도 볼 수 있다.
   - Linux는 `hostname -I`, Windows는 `ipconfig`의 "IPv4 주소"를 본다.
   - 보통 `192.168.x.x`나 `10.x.x.x` 모양이다. 와이파이를 바꾸면 IP도 바뀔 수 있으니, 그때는 `.env`를 고치고 2번 단계를 다시 한다.

3. Docker로 PostgreSQL과 MediaMTX를 띄운다. 다른 프로젝트와 겹치지 않게 PostgreSQL은 호스트의 5433번 포트를 쓴다. `LAN_IP`가 비어 있으면 이 명령이 오류로 알려 준다.

   ```bash
   docker compose up -d
   docker compose ps   # db와 mediamtx 두 줄이 Up이면 된다
   ```

   `LAN_IP`를 바꾼 뒤에는 `docker compose up -d`를 다시 실행하면 MediaMTX가 새 값으로 다시 만들어진다.

4. 앱을 실행하고 브라우저에서 http://localhost:8080 을 연다. 표는 서버가 켜질 때 자동으로 만든다.

   ```bash
   dx serve --platform web
   ```

   8080번 포트를 다른 프로그램이 쓰고 있으면 `--port`로 바꾼다. 이때는 아래 주소와 터널 명령의 8080도 같은 번호로 바꿔 읽는다.

   ```bash
   dx serve --platform web --port 8090
   ```

5. (라이브 송출을 해 볼 때) 다른 터미널에서 Cloudflare 터널을 연다. 자세한 내용은 아래 "휴대폰 접속 환경"에 있다.

   ```bash
   cloudflared tunnel --url http://localhost:8080
   ```

### 환경 변수

| 이름 | 필수 | 예시 / 기본값 | 뜻 |
|---|---|---|---|
| `DATABASE_URL` | 예 | `postgres://chzzk:chzzk@localhost:5433/chzzk` | PostgreSQL 접속 주소 |
| `DATA_DIR` | 아니요 | 기본 `./data` | 영상 보관 폴더. 안에 `videos/`와 업로드 중 임시 파일 `tmp/`가 생긴다. |
| `MAX_UPLOAD_BYTES` | 아니요 | 기본 `2147483648` (2 GiB) | 업로드 최대 크기(바이트) |
| `MEDIAMTX_WEBRTC_URL` | 아니요 | 기본 `http://localhost:8889` | 우리 서버가 송출·시청 연결 요청(WHIP/WHEP)을 넘길 MediaMTX 주소 |
| `MEDIAMTX_API_URL` | 아니요 | 기본 `http://localhost:9997` | 상태 감시기가 "지금 영상이 들어오는 경로" 목록을 읽을 MediaMTX 관리 API 주소 |
| `LAN_IP` | 예 (`docker compose`) | `192.168.0.10` | 이 컴퓨터의 와이파이 IP. 앱이 아니라 `docker compose`가 읽어 MediaMTX에 넘긴다(`MTX_WEBRTCADDITIONALHOSTS`). Docker 컨테이너 안에서는 컴퓨터의 와이파이 IP가 보이지 않기 때문이다. |
| `IP`, `PORT` | 아니요 | Dioxus 기본값 | 서버가 받을 주소와 포트 |

`.env` 예시:

```bash
DATABASE_URL=postgres://chzzk:chzzk@localhost:5433/chzzk
DATA_DIR=./data
MAX_UPLOAD_BYTES=2147483648
MEDIAMTX_WEBRTC_URL=http://localhost:8889
MEDIAMTX_API_URL=http://localhost:9997
LAN_IP=192.168.0.10
```

`.env.example`, `docker-compose.yml`의 값은 모두 내 컴퓨터에서만 쓰는 개발용 값이다. 실제 비밀 값은 저장소에 없고, `.env`와 보관 폴더(`/data`)는 git에서 제외한다. 송출 키는 방송을 시작할 때마다 서버가 새로 만들며 저장소나 설정 파일에 들어가지 않는다.

## 휴대폰 접속 환경 (라이브 송출)

휴대폰으로 송출하려면 두 가지가 필요하다.

1. **HTTPS 주소**: 휴대폰 브라우저는 `https://` 주소(또는 `localhost`)에서만 카메라를 쓰게 해 준다. `http://192.168.x.x:8080`으로 들어오면 송출 화면에 "HTTPS 주소로 접속해야 해요" 안내가 나온다. 그래서 Cloudflare 무료 터널로 HTTPS 주소를 만든다. 계정이나 로그인은 필요 없다.
2. **같은 와이파이**: 휴대폰과 컴퓨터를 같은 와이파이에 연결한다. 휴대폰의 모바일 데이터(LTE·5G)로는 송출되지 않는다.

### cloudflared 설치

```bash
# macOS
brew install cloudflared
cloudflared --version
```

다른 운영체제는 [Cloudflare 문서](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)에서 설치 파일을 받는다.

### 터널 실행

앱(`dx serve`)을 켜 둔 채 다른 터미널에서 실행한다.

```bash
cloudflared tunnel --url http://localhost:8080
```

몇 초 뒤 출력 중간에 아래처럼 생긴 주소가 나온다. 이 주소를 휴대폰 브라우저에서 연다.

```
Your quick Tunnel has been created! Visit it at (it may take some time to be reachable):
https://<무작위 단어들>.trycloudflare.com
```

- 주소는 터널을 실행할 때마다 바뀐다. 주소가 바뀌어도 앱이나 `.env`는 고칠 필요가 없다.
- 터널을 끄려면 그 터미널에서 Ctrl+C를 누른다.
- 처음 몇 초는 주소가 열리지 않을 수 있다. 잠시 뒤 새로고침한다.
- 컴퓨터에서 시청할 때는 터널 없이 http://localhost:8080 을 써도 된다. 터널 주소로 시청해도 된다.

## 카메라·마이크 권한

송출 화면(`/live/new`)에 들어가면 브라우저가 카메라와 마이크 사용을 묻는다. 둘 다 허용해야 방송을 시작할 수 있다.

### iOS Safari

- **처음 허용**: 터널 주소로 송출 화면을 열면 "카메라 및 마이크에 접근하려고 합니다" 창이 뜬다. "허용"을 누른다.
- **거절했을 때 다시 허용**
  1. 주소창 왼쪽의 "가가"(또는 페이지 설정) 아이콘을 누른다.
  2. "웹 사이트 설정"에서 카메라와 마이크를 "허용"(또는 "묻기")으로 바꾼다.
  3. 페이지를 새로고침한다.
- 위 메뉴에서 바꿀 수 없으면 설정 앱 → 앱 → Safari → (웹 사이트 설정의) 카메라, 마이크를 "묻기"나 "허용"으로 바꾼다. iOS 버전에 따라 설정 → Safari 아래에 있다.
- Safari는 "묻기"일 때 같은 주소에서도 다시 물을 수 있다. 터널 주소가 바뀌면 다른 사이트로 보고 처음부터 다시 묻는다.

### Android Chrome

- **처음 허용**: 송출 화면을 열면 "카메라 및 마이크를 사용하려고 합니다" 창이 뜬다. "이번 방문 동안 허용" 또는 "앱 사용 중에만 허용"을 누른다.
- **거절했을 때 다시 허용**
  1. 주소창 왼쪽의 사이트 정보 아이콘(자물쇠 또는 조절 아이콘)을 누른다.
  2. "권한"(또는 "사이트 설정")에서 카메라와 마이크를 "허용"으로 바꾼다.
  3. 페이지를 새로고침한다.
- 그래도 안 되면 휴대폰의 설정 → 애플리케이션 → Chrome → 권한에서 카메라와 마이크가 허용되어 있는지 확인한다. 휴대폰 자체가 Chrome의 카메라 사용을 막고 있으면 사이트 권한만으로는 쓸 수 없다.

권한이 없으면 송출 화면에 "카메라·마이크 권한이 없어 방송을 시작할 수 없어요…" 안내가 나오고 방송은 시작되지 않는다. 다른 앱(카메라, 영상 통화 등)이 카메라를 쓰고 있으면 "카메라를 다른 앱이 쓰고 있어요" 안내가 나온다. 그 앱을 닫고 다시 시도한다.

## 직접 확인 절차

### 1단계: 녹화 방송

준비: 재생해 볼 MP4 파일 하나. 휴대폰으로 찍은 영상이나 가지고 있는 MP4를 쓰면 된다. 없으면 ffmpeg로 10초짜리 시험 영상을 만들 수 있다.

```bash
ffmpeg -f lavfi -i testsrc=duration=10:size=640x360:rate=24 -f lavfi -i sine=frequency=440:duration=10 -c:v libx264 -pix_fmt yuv420p -c:a aac -movflags +faststart -shortest sample.mp4
```

1. **빈 목록**: http://localhost:8080 을 열면 "아직 방송이 없습니다"와 등록 버튼이 보인다.
2. **등록**: 머리글의 "녹화 올리기"를 누르고 제목과 MP4 파일을 골라 "등록"을 누른다. 진행률이 100%까지 오른 뒤 새 방송의 상세 화면으로 이동한다.
3. **거절**: 등록 화면에서 제목을 비우거나, MP4가 아닌 파일을 골라 등록하면 화면에 이유가 나오고 방송이 생기지 않는다.
4. **목록**: 첫 화면에 방금 등록한 방송이 카드로 맨 앞에 보인다. 하나 더 등록하면 새 방송이 맨 앞에 온다.
5. **상세**: 카드를 누르면 `/broadcasts/번호` 상세 화면이 나오고 제목과 등록 시각이 보인다. 이 주소를 새 창에 붙여 넣어도 같은 방송이 나온다.
6. **재생과 건너뛰기**: 재생 버튼을 누르면 영상이 재생된다. 재생 막대의 중간을 누르면 그 지점으로 바로 이동한다.
7. **없는 방송**: http://localhost:8080/broadcasts/999999 를 열면 "방송을 찾을 수 없습니다"가 보인다.
8. **재시작 뒤 유지**: `dx serve`를 멈췄다가(Ctrl+C) 다시 실행한다. DB도 다시 띄워 보려면 `docker compose down` 뒤 `docker compose up -d`를 한다(`-v`를 붙이면 데이터가 지워지므로 붙이지 않는다). 목록과 상세 화면에 방송이 그대로 있고 영상도 재생된다.

#### 선택 확인: 휴대폰에서 등록과 재생

컴퓨터와 휴대폰이 같은 와이파이에 있을 때, 다른 기기에서도 들어올 수 있게 서버를 띄운다.

```bash
dx serve --platform web --addr 0.0.0.0
```

컴퓨터의 내부 IP(맥: 시스템 설정 → Wi-Fi → 세부사항)를 확인하고, 휴대폰 브라우저에서 `http://<컴퓨터 IP>:8080`을 연다. 등록 화면에서 갤러리의 MP4 영상을 골라 등록하고, 상세 화면에서 재생해 본다. 영상 재생기에는 `playsinline`을 넣어 iOS Safari에서도 화면 안에서 재생된다. 아래 라이브 송출과 달리 녹화 방송 등록에는 HTTPS가 필요 없지만, 터널 주소로 들어와도 똑같이 된다.

### 2단계: 라이브 방송

준비

- 위 "실행 방법" 1~5단계: `.env`의 `LAN_IP`, `docker compose up -d`, `dx serve --platform web`, `cloudflared tunnel --url http://localhost:8080`
- 휴대폰과 컴퓨터를 같은 와이파이에 연결한다.
- 휴대폰 브라우저(iOS Safari 또는 Android Chrome)에서 터널의 `https://…trycloudflare.com` 주소를 연다.

1. **휴대폰에서 송출 시작**
   1. 휴대폰에서 머리글의 "라이브 시작"을 누른다.
   2. 카메라·마이크 권한을 묻는 창에서 허용한다. 후면 카메라 미리보기가 나온다. 미리보기에서는 내 목소리가 다시 나오지 않는다.
   3. 제목을 넣고 "방송 시작"을 누른다. 잠깐 "연결하는 중…"이 보인 뒤 빨간 LIVE 표시, "방송 중입니다", 시청 주소가 나온다.
   4. 제목을 비우고 시작하면 이유가 나오고 시작되지 않는다.
2. **컴퓨터의 "지금 라이브"에서 시청**
   1. 컴퓨터에서 http://localhost:8080 을 연다(이미 열려 있으면 5초 안에 저절로 갱신된다).
   2. 맨 위 "지금 라이브" 칸과 전체 목록에 방금 시작한 방송이 빨간 LIVE 표시, 시작 시각과 함께 보인다.
   3. 카드를 누르면 휴대폰 카메라 영상이 1초 안팎의 지연으로 나온다. 처음에는 소리가 꺼져 있으니 "소리 켜기"를 누른다.
   4. 휴대폰 송출 화면의 "복사"로 복사한 시청 주소를 다른 기기에서 열어도 같은 방송이 나온다.
3. **카메라 전환**: 휴대폰에서 "카메라 전환"을 누른다. 컴퓨터의 시청 화면이 끊기지 않고 전면 카메라 영상으로 바뀐다. 다시 누르면 후면으로 돌아간다.
4. **송출 종료**
   1. 휴대폰에서 "방송 종료"를 누른다. "방송을 종료했습니다"가 나오고 카메라가 꺼진다.
   2. 컴퓨터의 시청 화면에 몇 초(최대 5초 남짓) 안에 "방송이 종료되었습니다"가 나온다.
   3. 목록에서는 "지금 라이브" 칸이 사라지고(다른 방송 중인 방송이 없을 때), 전체 목록의 카드 표시가 "종료"로 바뀐다.
   4. 종료된 방송의 상세 화면에는 시작 시각과 방송한 시간이 나온다.
5. **송출 화면을 닫아 자동 종료**
   1. 1번처럼 새 방송을 시작하고, 컴퓨터에서 시청 화면을 띄워 둔다.
   2. 휴대폰에서 송출 중인 브라우저 탭을 닫는다.
   3. 몇 초 안에 컴퓨터의 시청 화면에 "방송이 종료되었습니다"가 나오고, 목록의 표시가 "종료"로 바뀐다.

### 화면 잠금·앱 전환 시 자동 종료

- 송출 중에 휴대폰 화면을 잠그거나, 다른 앱으로 가거나, 브라우저를 백그라운드로 보내면 휴대폰 브라우저가 카메라를 멈춘다. 영상이 끊기면 서버가 몇 초 안에 알아채고 방송을 **종료**로 바꾼다. 이것은 고장이 아니라 정해진 동작이다.
- 한 번 종료된 방송은 다시 방송 중으로 돌아가지 않는다. 계속하려면 "라이브 시작"으로 새 방송을 시작한다.
- 송출하는 동안에는 화면이 저절로 꺼지지 않게 막는다. 브라우저가 이 기능을 지원하지 않으면 "송출 중에는 화면을 켜 두세요" 안내가 나오니, 그때는 직접 화면을 켜 둔다. 휴대폰의 저전력 모드에서는 막기가 듣지 않을 수 있다.
- 와이파이가 끊겨도 같은 방식으로 종료된다.

### 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| "HTTPS 주소로 접속해야 해요" | 휴대폰에서 `http://…` 주소로 들어왔다. 터널의 `https://…trycloudflare.com` 주소로 연다. |
| "송출 서버와 연결하지 못했어요" | 휴대폰과 컴퓨터가 같은 와이파이인지, `.env`의 `LAN_IP`가 지금 와이파이 IP와 같은지, `LAN_IP`를 바꾼 뒤 `docker compose up -d`를 다시 했는지 확인한다. 손님용 와이파이·회사 와이파이처럼 기기끼리 막힌 망이면 다른 와이파이를 쓴다. 맥의 방화벽이 Docker의 연결을 막고 있지 않은지도 본다. |
| 시청 화면이 검게 나온다 | "소리 켜기"를 누르거나 영상을 한 번 누른다. 그래도 안 나오면 새로고침한다. |
| 터널 주소가 열리지 않는다 | `dx serve`가 켜져 있는지, 터널 명령의 포트가 `dx serve`의 포트와 같은지 확인한다. 막 만든 주소는 몇 초 뒤에 열린다. |

## 테스트

DB 테스트는 실제 PostgreSQL이 필요하다. `#[sqlx::test]`가 테스트마다 빈 임시 DB를 만들고 끝나면 지우므로, 개발용 데이터에는 영향이 없다. 영상 보관 폴더도 테스트마다 임시 폴더를 쓴다. 라이브 방송 테스트는 진짜 MediaMTX 대신 테스트 안에서 띄우는 **가짜 MediaMTX**(작은 axum 서버)를 쓰므로, MediaMTX 컨테이너나 카메라가 없어도 된다.

```bash
docker compose up -d
set -a; . ./.env; set +a
cargo test --no-default-features --features server
```

테스트는 서버를 띄우지 않고 HTTP 라우터에 요청을 직접 넣어, 응답과 그 뒤의 조회 결과를 본다. 상태 감시기는 "한 번 맞추기" 동작을 테스트가 직접 부르고, 지금 시각을 넘겨 30초 경과를 흉내 낸다.

| 묶음 | 확인하는 것 |
|---|---|
| 등록 | 제목과 MP4로 등록하면 201과 방송 번호가 오고 목록·조회에 나타난다. 영상이 보관 폴더에 저장되고 DB에는 상대 위치가 남는다. 목록은 최신순이다. 같은 제목도 된다. 앞뒤 공백은 지운다. |
| 거절 | 빈 제목, 공백뿐인 제목, 101자 제목, 아주 긴 제목 칸(메모리에 모으지 않음), 파일 없음, `.mp4`가 아닌 확장자, 확장자만 `.mp4`인 다른 파일, 최대 크기 초과(413), 중간에 끊긴 업로드. 모두 방송도 파일(임시 파일 포함)도 남기지 않는다. 거절된 뒤 다시 등록할 수 있다. |
| 영상 전송 | Range 없는 요청은 200과 전체 파일, Range 요청은 206과 정확한 바이트 범위. 없는 번호와 번호가 아닌 값은 404. |
| 재시작 | 같은 DB에 새로 연결하고 라우터를 다시 만들어도 방송과 영상이 그대로 조회된다. 라이브 방송의 상태와 시각도 그대로다. |
| 라이브 시작 | 201과 방송 번호·송출 키가 오고, 준비 상태라 목록·조회에는 아직 없다. 제목 규칙 위반은 400. |
| 송출 연결 | 키가 없거나 틀리면 401이고 가짜 MediaMTX에 요청이 가지 않는다. 맞는 키면 answer가 돌아오고 `Location`은 우리 서버 주소다. 준비가 아닌 방송은 409, 없는 번호는 404. 세션의 PATCH·DELETE도 키를 확인한다. |
| 상태 감시 | 경로에 영상이 들어오면 방송 중(시작 시각 기록, 목록에 나타남), 경로가 사라지면 종료(종료 시각 기록). 준비로 30초가 지나면 버려지고, 30초 전에는 그대로다. 종료된 방송은 경로가 다시 나타나도 방송 중이 되지 않는다. |
| 종료 요청 | 맞는 키면 204와 종료, 틀린 키면 401이고 상태 그대로. 준비 중에 종료하면 버려진다. 두 번 종료해도 204. |
| 시청 연결 | 방송 중일 때만 MediaMTX에 넘기고, 준비·종료는 409. 키는 필요 없다. |
| 섞인 목록 | 녹화 방송과 라이브 방송이 섞여도 정렬(녹화는 등록 시각, 라이브는 시작 시각)과 표시가 맞다. |
| 단위 | 제목 규칙(공백, 100자 경계, 한글·이모지 글자 수), 방송 번호 읽기(0, 앞자리 0, 숫자 아닌 글자, i64 범위), 한국 시간 표시, 송출 키(서로 다른 키, 맞는 키만 통과), 카드 표시와 방송한 시간, 송출 화면 안내 문구 |

1단계 테스트 32개는 고치지 않고 그대로 통과한다.
