# Spec: 3단계 인증·인가와 댓글

Status: ready-for-agent

## Problem Statement

2단계까지는 누구나 로그인 없이 방송을 만든다. 그래서 방송에 소유자가 없다.

- 제목을 잘못 써도 고칠 수 없다.
- 지우고 싶은 방송도 지울 수 없다.
- 라이브 방송은 그 방송을 시작한 화면이 가진 송출 키로만 끌 수 있다. 그 화면을 닫아 버리면 자동 종료를 기다리는 수밖에 없다.
- 시청자는 방송에 대해 말을 남길 방법이 없다.

이 스펙은 "치지직 만들기" 과제 4단계 중 3단계다. 1단계(녹화 방송, `.scratch/recorded-broadcasts/spec.md`)와 2단계(라이브 방송, `.scratch/live-broadcasts/spec.md`)의 기능을 모두 유지하며 확장한다.

채점은 소스와 README만 읽는 정적 평가다. 특히 두 가지를 본다.

- 권한 검사가 **서버에서** 이루어지는가. 화면에서 버튼만 숨기는 것으로는 안 된다.
- README에 비로그인 사용자·소유자·다른 사용자로 확인하는 절차가 있는가.

## Solution

**사용자와 로그인**
- 누구나 아이디와 비밀번호로 회원가입하고, 로그인·로그아웃한다.
- 로그인은 서버 세션과 `HttpOnly` 쿠키로 7일 동안 유지된다(ADR 0006).

**공개 범위**
- 시청, 목록, 댓글 읽기는 지금처럼 누구나 한다.
- 녹화 방송 등록, 라이브 방송 시작, 댓글 쓰기는 로그인한 사용자만 한다.
- 방송을 만든 사용자가 그 방송의 소유자다. 소유자만 할 수 있는 일은 아래와 같다.
  - 제목 수정(방송 중에도 된다)
  - 삭제(영상과 댓글까지 지운다)
  - 라이브 방송의 송출과 종료

**송출 키를 없앤다**: 송출과 종료도 소유자 확인으로 바꾼다(ADR 0005의 3단계 변경). 그래서 소유자는 송출 화면을 닫아도 다시 로그인해 상세 화면에서 방송을 끝낼 수 있다.

**댓글**
- 로그인한 사용자는 녹화 방송과 라이브 방송에 1~300자 댓글을 남기고, 자기 댓글을 지운다.
- 라이브 방송의 댓글은 3초마다 새로 고쳐진다.

**예전 방송**: 1·2단계에서 만든 방송은 "익명"(소유자 없음)으로 남는다. 누구도 수정·삭제할 수 없다.

## User Stories

### 회원가입·로그인

1. 방문자로서, 아이디와 비밀번호로 회원가입하고 싶다. 방송을 만들고 댓글을 남기기 위해서다.
2. 방문자로서, 아이디 규칙을 알고 싶다. 규칙은 2~20자, 한글·영문·숫자·밑줄이다. 어기면 이유를 보고 싶다.
3. 방문자로서, 비밀번호가 8자보다 짧거나 128자보다 길면 가입이 거절되고 이유를 보고 싶다.
4. 방문자로서, 이미 쓰는 아이디로 가입하면 "이미 쓰는 아이디예요"를 보고 싶다.
5. 방문자로서, 영문 대소문자만 다른 아이디(`Haroo`와 `haroo`)는 같은 아이디로 취급되기를 원한다. 다른 사람을 흉내 낸 아이디를 막기 위해서다.
6. 방문자로서, 가입이 끝나면 바로 로그인된 상태이기를 원한다.
7. 사용자로서, 아이디와 비밀번호로 로그인하고 싶다.
8. 사용자로서, 로그인에 실패하면 "아이디 또는 비밀번호가 맞지 않아요"를 보고 싶다. 아이디가 없는 경우와 비밀번호가 틀린 경우가 같은 문구다.
9. 사용자로서, 로그인이 7일 동안 유지되기를 원한다. 매번 로그인하지 않기 위해서다.
10. 사용자로서, 로그아웃하면 그 즉시 이 브라우저의 로그인이 무효가 되기를 원한다.
11. 사용자로서, 머리글에서 내가 로그인했는지(내 아이디)와 로그아웃 버튼을 보고 싶다.
12. 방문자로서, 머리글의 "로그인" 버튼으로 로그인 화면에 가고, 그곳에서 회원가입 화면으로 갈 수 있기를 원한다.
13. 방문자로서, 로그인이 필요한 화면(녹화 올리기, 라이브 시작)에 들어가면 로그인 화면으로 보내지고 싶다. 로그인한 뒤에는 원래 가려던 화면으로 돌아가고 싶다.
14. 사용자로서, 로그인 후 돌아가는 주소가 이 서비스 안의 주소이기를 원한다. 다른 사이트로 보내지는 링크에 속지 않기 위해서다.
15. 사용자로서, 내 비밀번호가 서버에 원문으로 저장되지 않기를 원한다.

### 방송 소유와 관리

16. 사용자로서, 내가 등록한 녹화 방송과 시작한 라이브 방송의 소유자가 내가 되기를 원한다.
17. 시청자로서, 목록 카드와 상세 화면에서 방송 소유자의 아이디를 보고 싶다. 예전 방송은 "익명"으로 보인다.
18. 소유자로서, 내 방송의 상세 화면에서 "제목 수정"과 "삭제" 버튼을 보고 싶다.
19. 소유자로서, 제목을 수정하고 싶다. 규칙은 등록 때와 같다(1~100자).
20. 소유자로서, 라이브 방송 중에도 제목을 고치고 싶다. 시청자 화면과 목록에 5초 안에 반영되기를 원한다.
21. 소유자로서, 방송을 삭제하기 전에 "정말 삭제할까요?" 확인을 받고 싶다.
22. 소유자로서, 녹화 방송을 삭제하면 방송 정보, 영상 파일, 댓글이 모두 사라지기를 원한다.
23. 소유자로서, 방송 중인 라이브 방송을 삭제하면 송출이 끊긴 뒤 사라지기를 원한다.
24. 소유자로서, 삭제한 방송의 주소가 "방송을 찾을 수 없습니다"가 되기를 원한다.
25. 소유자로서, 송출 화면을 닫아 버렸어도 상세 화면의 "방송 종료"로 내 라이브 방송을 끝내고 싶다.
26. 소유자로서, 2단계처럼 송출 화면에서 송출을 시작하고, 카메라를 전환하고, 종료하고 싶다.
27. 다른 사용자로서, 남의 방송에서 제목 수정·삭제·종료 버튼이 보이지 않기를 원한다.
28. 소유자로서, 다른 사용자가 화면을 거치지 않고 요청을 직접 보내도 내 방송을 수정·삭제·종료·송출할 수 없기를 원한다.
29. 소유자로서, 로그인하지 않은 사람도 내 방송을 수정·삭제·종료·송출할 수 없기를 원한다.
30. 사용자로서, 1·2단계에서 만든 소유자 없는 방송은 누구도 수정·삭제할 수 없기를 원한다.
31. 시청자로서, 보고 있던 방송이 삭제되면 몇 초 안에 "방송을 찾을 수 없습니다"를 보고 싶다.

### 등록과 송출의 로그인

32. 사용자로서, 로그인한 상태에서 1단계와 똑같이 녹화 방송을 등록하고 싶다. 진행률, 거절 규칙, 원자적 등록이 그대로다.
33. 방문자로서, 로그인하지 않고 녹화 방송을 등록하려 하면 서버가 거절하기를 원한다(화면은 로그인으로 보낸다).
34. 사용자로서, 로그인한 상태에서 2단계와 똑같이 라이브 방송을 시작하고 싶다.
35. 방문자로서, 로그인하지 않고 라이브 방송을 시작하려 하면 서버가 거절하기를 원한다.

### 댓글

36. 시청자로서, 녹화 방송과 라이브 방송 상세 화면 아래에서 댓글 목록을 보고 싶다. 로그인하지 않아도 된다.
37. 시청자로서, 댓글이 오래된 순으로, 작성자 아이디와 쓴 시각(한국 시간)과 함께 보이기를 원한다.
38. 사용자로서, 로그인한 상태에서 댓글을 쓰고 싶다. 쓰고 나면 내 댓글이 목록 끝에 바로 보인다.
39. 사용자로서, 빈 댓글이나 300자를 넘는 댓글은 거절되고 이유를 보고 싶다. 앞뒤 공백은 지운다.
40. 방문자로서, 로그인하지 않았으면 댓글 입력 칸 대신 "로그인하고 댓글을 남겨 보세요"와 로그인 링크를 보고 싶다.
41. 방문자로서, 로그인하지 않고 댓글 쓰기 요청을 직접 보내도 서버가 거절하기를 원한다.
42. 작성자로서, 내 댓글에만 "삭제" 버튼이 보이고, 누르면 그 댓글이 사라지기를 원한다.
43. 작성자로서, 다른 사용자가 요청을 직접 보내도 내 댓글을 지울 수 없기를 원한다.
44. 시청자로서, 라이브 방송을 보는 동안 댓글이 3초마다 새로 고쳐지기를 원한다. 채팅처럼 대화를 따라가기 위해서다.
45. 사용자로서, 종료된 라이브 방송에도 댓글을 남기고 싶다.
46. 소유자로서, 방송을 삭제하면 그 방송의 댓글도 함께 사라지기를 원한다.

### 1·2단계 기능, 운영자, 채점자

47. 시청자로서, 1·2단계의 목록, 상세, 재생, 건너뛰기, 라이브 시청, 지금 라이브 칸, 상태 표시가 그대로 동작하기를 원한다.
48. 운영자로서, 서버를 재시작해도 사용자, 로그인 세션, 방송 소유, 댓글이 그대로 남기를 원한다.
49. 운영자로서, 다른 사이트가 사용자 몰래 우리 서비스에 상태를 바꾸는 요청을 보내지 못하기를 원한다(CSRF).
50. 채점자로서, README에서 공개 범위 표를 보고 싶다. 표에는 무엇을 누가 할 수 있는지가 있어야 한다.
51. 채점자로서, README에서 확인 절차를 따라 하고 싶다. 계정 두 개와 시크릿 창을 써서 비로그인·소유자·다른 사용자의 허용과 거절을 보고, 화면을 거치지 않는 요청 예시로도 거절을 본다.
52. 채점자로서, README에서 3단계 범위, 범위 밖, 한계(로그인 시도 횟수 제한 없음)를 보고 싶다.
53. 채점자로서, 3단계 시점의 코드를 `step-3` 태그로 보고 싶다. `step-1`과 `step-2`는 그대로 남아야 한다.

## Implementation Decisions

- **용어**: GLOSSARY.md의 사용자, 로그인, 소유자, 댓글, 작성자와 기존 방송 용어를 쓴다. 송출 키는 사라진다.
- **스키마(티켓마다 날짜·시각 이름의 마이그레이션, 모두 넷)**:
  - 사용자 표
    - 사용자 번호(identity)
    - 아이디: 대소문자를 무시해 겹치지 않게 하는 고유 인덱스, 2~20자 `CHECK`
    - 비밀번호 해시(Argon2id, PHC 문자열)
    - 가입 시각
  - 세션 표
    - 세션 값 해시(SHA-256, 기본 키)
    - 사용자 번호
    - 만든 시각, 만료 시각
  - 방송 표
    - 소유자(사용자 번호, 비어 있을 수 있음)를 더한다.
    - 송출 키 해시 칸과 그것을 요구하던 `CHECK`를 없애고, 종류별 `CHECK`를 다시 만든다. 기존 행은 소유자 없음이 된다.
  - 댓글 표
    - 댓글 번호
    - 방송 번호: 방송을 지우면 함께 지워진다
    - 작성자
    - 본문: 1~300자 `CHECK`
    - 쓴 시각
- **모듈**:
  - **계정**: 아이디·비밀번호 규칙, 가입, 비밀번호 확인, 세션 만들기·찾기·지우기.
    - 비밀번호 해시는 CPU를 쓰므로 블로킹 작업으로 돌린다.
    - 로그인 실패는 이유를 구분하지 않는다. 없는 아이디여도 해시 비교를 한 번 해서 응답 시간 차이를 줄인다.
  - **현재 사용자 확인**: 요청의 쿠키에서 세션을 찾아 "비로그인 / 사용자"를 알려 주는 axum 추출기 하나. 모든 권한 검사는 이것을 거친다. 확인 결과는 셋이다.
    - 로그인 필요 → 401
    - 권한 없음 → 403
    - 소유자 확인 → 방송의 소유자가 현재 사용자인지
  - **방송 관리**: 제목 수정, 삭제. 삭제 순서는 아래와 같다.
    - 라이브 방송 중이면 MediaMTX 송출을 끊고 종료한다.
    - 방송 행을 지운다. 댓글은 연쇄로 지워진다.
    - 녹화 방송이면 그다음 영상 파일을 지운다. 행을 먼저 지워야 "파일 없이 남은 방송"이 생기지 않는다(코드 검토에서 이 순서로 정함).
  - **댓글**: 쓰기, 방송별 목록(오래된 순), 지우기.
  - 기존 모듈 변경
    - 등록과 라이브 시작은 로그인을 요구하고 소유자를 기록한다.
    - 송출 연결(WHIP POST·PATCH·DELETE)과 종료는 소유자를 요구한다.
    - 시청(WHEP)과 목록·상세 조회는 그대로 공개다.
    - 목록·상세 조회 결과에 소유자 아이디(없으면 비어 있음)를 더한다.
- **쿠키와 CSRF**:
  - 쿠키 이름은 `chzzk_session`이다. `HttpOnly`, `SameSite=Lax`, `Path=/`, 7일 `Max-Age`를 붙인다.
  - 요청이 HTTPS로 들어왔으면 `Secure`를 붙인다. 터널은 `X-Forwarded-Proto: https`를 보낸다.
  - 상태를 바꾸는 모든 요청(POST·PATCH·DELETE)은 `Origin` 헤더가 있으면 요청 주소와 같은 출처인지 확인하고, 다르면 403이다. `Origin`이 없는 요청(테스트, curl)은 쿠키 규칙만 따른다.
- **HTTP 계약**: 모두 직접 덧붙인 axum 라우트다. 본문과 응답은 JSON이고, 실패는 1·2단계와 같은 `{code, message}`다.
  - 상태 코드
    - 로그인이 필요한데 없으면 401(`login_required`)
    - 로그인했지만 권한이 없으면 403(`forbidden`)
    - 없는 방송·댓글은 404
  - **계정**
    - `POST /api/auth/signup` `{username, password}`
      - 성공하면 201과 세션 쿠키, `{username}`을 준다.
      - 규칙 위반은 400, 이미 쓰는 아이디는 409다.
    - `POST /api/auth/login`: 성공하면 200과 쿠키를 준다. 실패는 401(`bad_credentials`)이다.
    - `POST /api/auth/logout`: 204. 세션을 지우고 쿠키를 만료시킨다. 로그인하지 않았어도 204다.
    - `GET /api/auth/me`: 200과 `{username}` 또는 `{username: null}`.
  - **방송**
    - `POST /api/broadcasts`(등록)와 `POST /api/live`(라이브 시작)는 로그인이 필요하다.
    - `POST /api/live`의 응답은 `{id}`다. 송출 키는 없다.
    - `PATCH /api/broadcasts/{번호}` `{title}`
      - 소유자면 200이다.
      - 비로그인은 401, 소유자가 아니거나 소유자 없는 방송이면 403이다.
      - 제목 위반은 400, 없거나 보이지 않는 방송은 404다.
    - `DELETE /api/broadcasts/{번호}`: 소유자면 204이고, 권한 규칙은 위와 같다.
  - **라이브 송출**
    - `POST /api/live/{번호}/whip`과 세션 PATCH·DELETE, `POST /api/live/{번호}/end`는 송출 키 대신 소유자를 요구한다(401/403).
    - 나머지 동작(409, `Location` 바꾸기, 종료 규칙)은 2단계와 같다.
  - **댓글**
    - `GET /api/broadcasts/{번호}/comments`: 누구나. 오래된 순으로 `[{id, author, body, created_at, mine}]`을 준다. `mine`은 현재 사용자가 작성자인지다.
    - `POST /api/broadcasts/{번호}/comments` `{body}`: 로그인 필요. 성공하면 201과 그 댓글을 준다. 본문 위반은 400, 없는 방송은 404다.
    - `DELETE /api/comments/{댓글 번호}`: 작성자면 204, 아니면 403, 비로그인은 401, 없으면 404다.
- **화면**:
  - **머리글**
    - 로그인 전에는 "로그인", 후에는 "아이디님"과 "로그아웃"이 보인다.
    - "라이브 시작"과 "녹화 올리기"는 그대로 둔다. 로그인 전에 누르면 로그인 화면으로 간다.
  - **로그인·회원가입**
    - `/login?next=<원래 주소>`와 `/signup`
    - `next`는 `/`로 시작하고 `//`로 시작하지 않는 이 서비스 안의 주소만 받는다. 아니면 첫 화면으로 간다.
  - **등록·송출 화면**: 로그인하지 않았으면 들어오자마자 로그인 화면으로 보낸다. 서버도 거절한다.
  - **목록 카드**: 소유자 아이디(없으면 "익명")를 더한다.
  - **상세 화면**
    - 소유자 아이디를 보여 준다.
    - 현재 사용자가 소유자면 "제목 수정"(제자리 입력), "삭제"(확인 창), 방송 중이면 "방송 종료"를 보여 준다.
    - 라이브 방송 화면은 5초마다 상태를 확인할 때 제목도 함께 갱신한다. 방송이 사라지면 "방송을 찾을 수 없습니다"를 보여 준다.
  - **댓글 칸**: 상세 화면 아래에 둔다.
    - 목록을 보여 준다.
    - 로그인했으면 입력 칸과 "등록" 버튼을, 아니면 로그인 안내를 보여 준다.
    - 내 댓글에는 "삭제"가 붙는다.
    - 라이브 방송(방송 중)이면 3초마다 다시 불러온다.
  - **송출 화면**: 송출 키를 다루던 코드를 지운다. 같은 출처 요청이라 쿠키가 실리므로 나머지 흐름(시작, 카메라 전환, 종료, 화면을 떠날 때 keepalive 종료)은 그대로다.
- **설정**: 새 환경변수는 없다. 세션 유지 기간(7일)과 규칙 값은 코드 상수다. `.env.example`에는 바뀌는 것이 없다.
- **README**: 1·2단계 내용을 유지하고 아래를 더한다.
  - 3단계 범위, 범위 밖과 한계
  - 공개 범위 표
  - 확인 절차: 일반 창(사용자 A), 시크릿 창(사용자 B), 또 다른 시크릿 창(비로그인)으로 각 동작의 허용·거절을 본다
  - 화면을 거치지 않는 요청으로 거절을 확인하는 `curl` 예시. 다른 사용자의 쿠키로 남의 방송을 삭제하면 403이 나오는 것을 본다.
  - 테스트 결과
- **제출**: 같은 저장소에 이어 올리고 `step-3` 태그를 붙여 `tree/step-3`으로 제출한다. 2단계 회고의 변경(Rust 버전 고정, MediaMTX 설정 위치, 문서)도 함께 올라간다.

## Testing Decisions

- 좋은 테스트는 외부 동작만 검증한다. HTTP 요청을 보내고 응답과 그 뒤의 조회 결과로 판단한다. SQL, 해시 방식, 쿠키 값의 모양은 검증하지 않는다(쿠키 속성 `HttpOnly`, `SameSite`는 계약이라 본다).
- **주 seam: 서버 HTTP 라우터 전체**(1·2단계와 같다). `#[sqlx::test]` 임시 DB, 임시 보관 폴더, 가짜 MediaMTX를 쓴다.
  - 테스트 손님은 세 종류다. 쿠키 없는 비로그인, 진짜 가입·로그인 API로 쿠키를 받은 소유자, 다른 아이디로 쿠키를 받은 다른 사용자.
  - 이 손님들을 만드는 공용 도우미를 둔다.
- **검증 대상**
  - **계정**
    - 가입하면 201과 쿠키(`HttpOnly`, `SameSite=Lax`)가 온다. 그 쿠키로 `me`가 아이디를 돌려준다.
    - 규칙 위반은 400이다.
    - 같은 아이디는 대소문자가 달라도 409다.
    - 로그인 성공은 200이다. 없는 아이디와 틀린 비밀번호는 둘 다 401이고 같은 메시지다.
    - 로그아웃 뒤 같은 쿠키로 `me`는 null이고, 로그인이 필요한 요청은 401이다.
    - 만료 시각이 지난 세션은 로그인으로 치지 않는다.
  - **방송 권한**: 아래 각 동작에 대해 비로그인 401, 다른 사용자 403, 소유자 성공을 본다. 거절된 뒤에는 방송·상태·파일이 그대로다.
    - 등록과 라이브 시작(비로그인 401, 로그인하면 소유자가 기록된다)
    - 제목 수정, 삭제
    - 송출 연결 POST·PATCH·DELETE(거절이면 가짜 MediaMTX에 요청이 가지 않는다)
    - 종료
  - **소유자 없는 방송**: 수정·삭제는 누구든 403이다.
  - **삭제**
    - 녹화 방송을 지우면 영상 파일과 댓글이 사라지고, 이후 조회는 404다.
    - 방송 중인 라이브 방송을 지우면 가짜 MediaMTX에 송출 끊기 요청이 간다.
  - **제목 수정**: 수정하면 목록·상세에 새 제목이 보인다. 위반은 400이다.
  - **댓글**
    - 비로그인 쓰기는 401이다.
    - 로그인 쓰기는 201이고, 목록 끝에 작성자와 함께 보인다.
    - 빈 댓글과 301자 댓글은 400이다.
    - 목록은 누구나 오래된 순으로 본다. `mine`은 작성자에게만 참이다.
    - 남의 댓글 삭제는 403, 내 댓글 삭제는 204다.
    - 없는 방송에 쓰면 404다.
  - **CSRF**: 다른 출처의 `Origin`을 단 상태 변경 요청은 쿠키가 있어도 403이다.
  - **재시작**: 같은 DB에 새로 연결해도 쿠키 로그인, 소유자, 댓글이 그대로다.
- **1·2단계 테스트**: 각 테스트의 본문(보내는 내용과 확인하는 내용)은 바꾸지 않는다. 로그인이 새 전제 조건이 되었으므로 등록 요청과 라이브 시작을 만드는 **공용 도우미에서만** 로그인한 사용자의 쿠키를 붙인다. 송출 키를 쓰던 2단계 도우미는 소유자 쿠키를 쓰도록 바꾼다. 송출 키 자체를 확인하던 테스트(키 해시 저장, 틀린 키 401)는 같은 의미의 소유자 테스트(다른 사용자 403, 비로그인 401)로 바꾼다. 이 예외를 CODING_STANDARDS.md에 적는다.
- **보조**: 아이디·비밀번호·댓글 본문 규칙 단위 테스트(경계값, 한글, 이모지).
- 선행 사례는 1·2단계의 라우터 테스트, `LiveApp`, 가짜 MediaMTX, 재시작 테스트다.
- 화면(버튼 노출, 로그인 뒤 돌아가기, 댓글 3초 갱신)은 구현 중에 브라우저 두 개(일반 창·시크릿 창)로 직접 확인하고, README 절차로 남긴다.

## Out of Scope

- 이메일, 이메일 인증, 비밀번호 찾기·바꾸기, 회원 탈퇴, 프로필(사진·소개)
- 소셜 로그인, 2단계 인증
- 로그인 시도 횟수 제한(무차별 대입 방지). README에 한계로 적는다.
- 댓글 수정, 답글, 좋아요, 신고, 소유자가 남의 댓글을 지우는 관리 기능
- 관리자 역할, 방송 공개·비공개 설정
- "내 방송" 모아 보기 화면
- 실시간 알림 장치(WebSocket). 댓글과 상태는 주기적으로 다시 묻는다.
- 녹화 방송의 영상 바꾸기, 라이브 다시 보기
- 실제 서버 배포
