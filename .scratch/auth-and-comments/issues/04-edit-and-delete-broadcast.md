# 04: 방송 제목 수정과 삭제

**What to build:** 소유자가 상세 화면에서 방송 제목을 고치고(`PATCH /api/broadcasts/{번호}`), 방송을 삭제한다(`DELETE /api/broadcasts/{번호}`). 둘 다 비로그인은 401이다. 소유자가 아니거나 소유자 없는 방송이면 403이다. 없거나 보이지 않는 방송은 404다.

- **수정**
  - 제목 규칙은 등록과 같다(1~100자, 위반은 400).
  - 방송 중인 라이브도 고칠 수 있다.
  - 라이브 시청 화면은 5초마다 상태를 확인할 때 제목도 갱신한다.
- **삭제**
  - "정말 삭제할까요?" 확인을 거친다.
  - 녹화 방송이면 영상 파일을 지운다.
  - 방송 중인 라이브면 MediaMTX 송출을 끊고 종료한 뒤 지운다.
  - 방송 행을 지우면 그 방송의 댓글도 함께 지워진다. 연쇄 삭제는 05의 댓글 표가 정한다.
  - 지운 방송의 주소와 보고 있던 시청 화면은 "방송을 찾을 수 없습니다"가 된다.

상세 화면에는 소유자에게만 "제목 수정"(제자리 입력)과 "삭제" 버튼이 보인다. 03이 같은 화면에 "방송 종료" 버튼을 더하므로, 소유자 버튼 자리는 함께 쓸 수 있게 둔다.

- [x] 제목 수정은 이렇게 응답한다.
  - 소유자는 200이고, 목록·상세에 새 제목이 보인다. 제목 위반은 400이다
  - 비로그인은 401, 다른 사용자는 403이며 제목이 그대로다
  - 소유자 없는 방송은 누구든 403이다
- [x] 삭제는 이렇게 응답한다.
  - 소유자는 204다. 녹화 방송은 영상 파일까지 사라지고, 이후 조회와 영상 요청은 404다
  - 비로그인 401, 다른 사용자 403, 소유자 없는 방송 403이다. 거절되면 방송과 파일이 그대로다
- [x] 방송 중인 라이브를 지우면 가짜 MediaMTX에 송출 끊기 요청이 가고, 방송은 사라진다
- [x] 화면에서 소유자에게만 버튼이 보인다. 제목 수정이 시청 화면에 5초 안에 반영되고, 삭제 확인 창이 뜬다(브라우저로 직접 확인)

브라우저 확인(2026-11-17, `localhost`=소유자, `127.0.0.1`=다른 사용자, ffmpeg WHIP 송출): 소유자에게만 "제목 수정"·"삭제"가 보였다. 방송 중 제목 수정이 다른 사용자의 시청 화면에 약 3.6초 만에 반영됐다. "삭제"는 `window.confirm("정말 삭제할까요?")`을 부르고, 취소하면 그대로, 확인하면 목록으로 간다(확인 창은 자동화 도구에서 `window.confirm`을 바꿔 끼워 응답했다). 라이브 삭제 뒤 MediaMTX 로그에 송출 세션 종료가 찍혔고 시청 화면은 "방송을 찾을 수 없습니다"가 됐다. 녹화 삭제 뒤 주소는 404 화면, 영상 요청은 404, 영상 파일은 사라졌다.
