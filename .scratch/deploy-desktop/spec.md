# Spec: ⑥ 도메인·OCI 배포와 Windows·macOS·iOS 앱

과제 원문(체크리스트 포함): `assignment.md`

Status: ready-for-agent

## Problem Statement

지금까지 만든 치지직 서비스(녹화 방송, 라이브 방송, 로그인·소유자·댓글, 후원)는 내 컴퓨터에서만 돈다. 다른 사람이 들어올 공개 주소가 없고, 컴퓨터를 끄면 서비스도 멈춘다. 방송을 보려면 웹 브라우저로만 들어와야 하고, PC나 아이폰에서 바로 여는 앱이 없다. 코드를 고칠 때마다 손으로 빌드하고 올려야 한다.

이 스펙은 "치지직 만들기" 과제 ⑥이다. 1~4단계 기능을 모두 유지하며 확장한다. ⑤(로컬 오토스케일, 마감 12/12)는 이 스펙 뒤에 따로 하되, 이 스펙의 Docker 이미지와 "상태는 앱 밖에" 구성을 그대로 이어 쓴다.

채점의 성격이 다르다.

- AI는 소스·설정·README만 읽는다.
- 도메인 등록, OCI 가동, HTTPS, 다운로드와 Windows·macOS 실행은 강사가 직접 확인한다.
- 그래서 실제로 동작해야 한다. 강사 요구로 iOS 앱 배포까지 한다.

## Solution

- **배포 서버**: 치지직 백엔드와 웹 화면을 오라클 클라우드 싱가포르 리전의 Always Free ARM VM 한 대(`VM.Standard.A1.Flex` 2 OCPU·12 GB, Ubuntu 24.04)에 Docker Compose로 올린다(ADR 0008).
- **도메인과 HTTPS**
  - 사용자가 Cloudflare에서 산 `haroobuzii.com`의 하위 주소 `chzzk.haroobuzii.com`을 배포 서버로 연결한다.
  - Caddy가 Let's Encrypt 인증서로 HTTPS를 제공한다.
  - Cloudflare는 "DNS only"로 둔다.
- **상태 확인**: 상태 확인 주소 `/healthz`가 서버가 살아 있는지 알려 준다.
- **앱**
  - Windows·macOS·iOS 앱은 같은 Dioxus 코드로 만든다.
  - 배포 서버의 방송 목록을 보고, 녹화 방송을 재생하고, 라이브 방송을 시청한다.
  - 로그인·댓글·후원은 "웹에서 열기"로 기본 브라우저를 연다(ADR 0009).
- **다운로드 페이지**: 배포 서버의 `/download`가 OS별 파일 링크, 지원 아키텍처, 설치·실행 방법, iOS TestFlight 공개 링크를 보여 준다.
- **자동 빌드·배포**: main에 푸시하면 GitHub Actions가 자동으로 아래를 한다.
  - 테스트를 돌린다.
  - 배포 서버를 새 버전으로 바꾼다.
  - Windows·macOS 앱 파일을 GitHub Releases에 올린다.
  - iOS 앱을 TestFlight에 올린다.
  - 맥 앱은 Apple 개발자 계정으로 서명·공증한다(ADR 0010).
- **돈과 비밀 값**: 배포 서버에서도 토스는 테스트 모드다. 비밀 값은 서버의 `.env`와 GitHub Secrets에만 둔다. 오라클은 무료 모양만 쓰고 $1 예산 알림을 건다.

## User Stories

### 시청자와 사용자 (웹)

1. 시청자로서, `https://chzzk.haroobuzii.com`으로 어디서든 치지직에 들어오고 싶다. 내 컴퓨터가 꺼져 있어도 서비스가 돌아야 한다.
2. 시청자로서, 주소창에 자물쇠(HTTPS)가 보이기를 원한다. 안전한 사이트인지 알기 위해서다.
3. 시청자로서, `http://`로 들어와도 자동으로 `https://`로 옮겨지기를 원한다.
4. 사용자로서, 1~4단계의 모든 기능을 배포된 사이트에서 똑같이 쓰고 싶다. 녹화 올리기, 재생, 라이브 송출·시청, 로그인, 댓글, 후원이다.
5. 사용자로서, 2 GiB까지의 녹화 영상을 배포된 사이트에 올리고 싶다.
6. 송출자로서, 휴대폰 LTE·5G에서도 라이브 송출을 하고 싶다. 배포 서버에는 공인 IP가 있으니 같은 와이파이가 아니어도 된다.
7. 송출자로서, 터널 없이 배포 주소에서 바로 카메라 권한을 받고 싶다. 배포 주소는 HTTPS다.
8. 후원자로서, 배포된 사이트에서도 테스트 결제로 후원하고 싶다. "테스트 결제 · 실제로 돈이 나가지 않아요" 표시가 보여야 한다.
9. 사용자로서, 배포 서버를 다시 켜거나 새 버전으로 바꿔도 계정, 방송, 영상, 댓글, 후원이 그대로 남기를 원한다.

### 다운로드와 앱

10. 방문자로서, 웹 화면 머리글이나 첫 화면에서 "앱 다운로드"로 다운로드 페이지에 가고 싶다.
11. 방문자로서, 다운로드 페이지에서 내 OS에 맞는 파일 링크를 보고 싶다. Windows x64, macOS Apple Silicon, macOS Intel, iOS(TestFlight)다.
12. 방문자로서, 다운로드 페이지에서 지원 아키텍처와 최소 OS 버전, 설치·실행 방법을 보고 싶다.
13. Windows 사용자로서, 설치 파일을 내려받아 설치하고 실행하고 싶다. SmartScreen 경고가 뜨면 "추가 정보 → 실행"으로 넘어가는 방법을 안내받는다.
14. macOS 사용자로서, 내려받은 앱을 경고 없이 열고 싶다. 앱은 서명·공증되어 있다.
15. 아이폰 사용자로서, TestFlight 공개 링크로 앱을 설치하고 싶다.
16. 앱 사용자로서, 앱을 열면 배포 서버의 방송 목록을 보고 싶다. "지금 라이브" 칸, 녹화·LIVE·종료 표시, 소유자 아이디, 시각이 나온다.
17. 앱 사용자로서, 녹화 방송을 눌러 앱 안에서 재생하고, 중간으로 건너뛰고 싶다.
18. 앱 사용자로서, 방송 중인 라이브를 앱 안에서 시청하고 싶다. 플랫폼에서 WebRTC를 쓸 수 없으면 "웹에서 시청하기"로 안내받는다.
19. 앱 사용자로서, 방송 화면의 "웹에서 열기"를 눌러 기본 브라우저에서 같은 방송 페이지를 열고 싶다. 로그인, 댓글, 후원을 하기 위해서다.
20. 앱 사용자로서, 목록이 저절로 갱신되기를 원한다(라이브 상태 5초).
21. 앱 사용자로서, 서버에 연결할 수 없으면 "서버에 연결할 수 없어요"와 "다시 시도"를 보고 싶다.
22. 앱 사용자로서, 앱 안에도 "테스트 서비스" 같은 혼동 없는 표시를 보고 싶다. 앱에서는 결제가 없다.

### 운영자 (사용자 본인)

23. 운영자로서, main에 푸시하면 테스트가 통과한 경우에만 배포 서버가 새 버전으로 바뀌기를 원한다.
24. 운영자로서, 배포가 끝난 뒤 자동 검사가 `https://chzzk.haroobuzii.com/healthz`를 불러 정상인지 확인하기를 원한다. 실패하면 빨간불이 들어온다.
25. 운영자로서, main에 푸시하면 Windows·macOS 앱 파일이 새로 만들어져 다운로드 링크가 최신을 가리키기를 원한다.
26. 운영자로서, main에 푸시하면 iOS 앱이 TestFlight에 새 빌드로 올라가기를 원한다(Apple 개발자 승인 뒤).
27. 운영자로서, `/healthz`로 서버, DB, 중계소 상태를 한눈에 보고 싶다.
28. 운영자로서, 배포 서버를 처음부터 다시 만들 수 있게 모든 절차가 스크립트와 README로 남기를 원한다. 오라클 리소스, 서버 준비, DNS, 비밀 값 넣기가 들어간다.
29. 운영자로서, 비밀 값이 저장소에 들어가지 않기를 원한다. 토스 키, DB 비밀번호, SSH 키, Apple 인증서, App Store Connect 키다.
30. 운영자로서, 오라클 무료 범위를 넘는 청구가 생기면 바로 메일을 받기를 원한다($1 예산 알림, 이미 설정함).
31. 운영자로서, 무료 VM이 노는 것으로 보여 오라클에 회수되지 않기를 원한다. 회수 조건과 대응을 README에 적는다.
32. 운영자로서, 만든 리소스 목록과 지우는 방법을 README에서 보고 싶다. 과제가 끝난 뒤 비용이 생기지 않게 하기 위해서다.

### 채점자와 강사

33. 강사로서, README에서 등록한 도메인, 최초 등록·갱신 비용($11.17 / $11.17/년), DNS와 HTTPS 구성을 보고 싶다.
34. 강사로서, README에서 VM 리전·shape·OCPU·메모리와 Always Free 선택 근거를 보고 싶다. 재고 부족으로 Pay As You Go로 바꾼 이유도 적혀 있어야 한다.
35. 강사로서, README에서 공개 주소와 OS별 설치·실행 확인 절차, 테스트한 OS·아키텍처와 결과를 보고 싶다.
36. 강사로서, 외부 네트워크에서 공개 링크로 앱을 내려받아 실행해 보고 싶다.
37. 채점자로서, 서버 배포 설정, 앱 빌드·패키징 설정, 다운로드 페이지 소스를 저장소에서 보고 싶다.
38. 채점자로서, ⑥ 시점의 코드를 `step-6` 태그로 보고 싶다.

## Implementation Decisions

- **용어**: GLOSSARY.md의 배포 서버, 앱(데스크톱 앱·iOS 앱), 다운로드 페이지와 기존 용어를 쓴다. 과제 원문의 "클라이언트"는 앱이다.
- **배포 서버 인프라**(이미 일부 만듦)
  - 오라클 싱가포르(홈 리전, 가용 영역 1개)에 아래를 둔다.
    - VCN `chzzk-vcn`, 인터넷 게이트웨이, 공개 서브넷
    - 보안 목록: TCP 22·80·443, UDP 8189 들어옴 허용
    - VM `chzzk`: A1.Flex 2 OCPU·12 GB, Ubuntu 24.04 aarch64, 부트 볼륨 100 GB, 공인 IP
  - 만드는 과정은 OCI CLI 스크립트와 cloud-init으로 저장소에 둔다. cloud-init은 Docker 설치, 서버 안 iptables 80·443·UDP 8189 열기, 앱 폴더 준비를 한다.
  - A1 재고 부족이면 다시 시도하고, 계정을 Pay As You Go로 바꾼 사실과 이유를 README에 남긴다.
  - 무료 대안(E2.1.Micro 1 GB)은 메모리가 부족해 쓰지 않은 이유도 적는다.
- **배포 서버 구성(Docker Compose, 운영용 파일 하나)**
  - 서비스 넷
    - Caddy
    - 앱: GHCR의 ARM64 이미지
    - PostgreSQL: 볼륨
    - MediaMTX: 개발용과 같은 설정. 추가 ICE 후보에 VM 공인 IP를 넣는다
  - 영상 보관 폴더는 볼륨이다.
  - DB 비밀번호는 서버에서 처음 한 번 무작위로 만든다(개발용 `chzzk` 비밀번호를 쓰지 않는다).
  - 서버의 `.env`에 들어가는 값
    - `DATABASE_URL`
    - 토스 테스트 키(사용자 것)
    - `PUBLIC_IP`(MediaMTX용)
    - `LIVE_PATH_PREFIX` 기본값
  - **Caddy**
    - `chzzk.haroobuzii.com`의 인증서를 자동으로 받는다.
    - HTTP를 HTTPS로 옮긴다.
    - 앱으로 프록시한다(`X-Forwarded-Proto` 전달 → 쿠키 `Secure`).
    - 업로드를 위해 요청 본문 2 GiB와 넉넉한 본문 읽기 시간을 준다.
  - MediaMTX의 HTTP 포트는 지금처럼 서버 안에만 열고, 앱 서버가 WHIP/WHEP를 중계한다. UDP 8189만 밖에 연다.
- **DNS**: Cloudflare DNS에 `chzzk` A 레코드를 배포 서버 공인 IP로, 프록시 끔(DNS only)으로 둔다. 다른 서비스는 나중에 하위 주소로 더한다.
- **백엔드 변경**
  - **상태 확인 `GET /healthz`**
    - DB에 간단한 질의가 되면 200이고, 아니면 503이다.
    - 본문은 `{status, db, mediamtx, version}`이다. MediaMTX 관리 API에 닿지 않으면 `mediamtx: "unreachable"`이지만, 녹화·로그인은 되므로 200을 유지한다.
    - `version`은 빌드할 때 넣은 커밋 해시다.
  - **앱용 CORS**
    - 앱 웹뷰 출처(Windows `http://dioxus.index.html`, macOS·iOS `dioxus://index.html` 계열)에서 오는 요청만 허용한다.
    - 대상은 공개 읽기 경로(방송 목록·단건·영상)와 시청 연결(WHEP POST·PATCH·DELETE)뿐이다. 쿠키는 허용하지 않는다(`credentials` 없음).
    - 나머지 경로와 상태 변경 요청은 지금처럼 같은 출처만 받는다(ADR 0006 CSRF).
  - 앱이 쓸 방송 목록·단건 조회는 기존 공개 API를 그대로 쓴다. 필요하면 앱이 부르기 쉬운 GET JSON 주소를 문서화한다.
  - 다운로드 페이지(`/download`)를 웹 화면에 더한다. 머리글이나 첫 화면에서 링크한다.
    - 파일 링크는 GitHub Releases의 고정 태그 주소다(아래 "앱 빌드·배포").
    - TestFlight 링크는 설정 값이다(비어 있으면 "준비 중").
- **앱**
  - 같은 크레이트에 앱용 기능(feature)을 더한다. 서버 기능 없이 데스크톱·iOS로 빌드한다.
  - 서버 주소는 빌드할 때 정한다. 기본값은 `https://chzzk.haroobuzii.com`이다.
  - 앱 화면은 웹 화면의 목록·상세 컴포넌트를 최대한 재사용한다.
  - **앱의 서버 연결 모듈**(테스트 대상)은 아래 일을 한다.
    - 방송 목록·단건을 JSON으로 받는다(Rust HTTP, 웹뷰 fetch가 아님).
    - 녹화 영상 주소(절대 URL), WHEP 주소, "웹에서 열기" 주소를 만든다.
    - 연결 실패를 사용자 문구로 바꾼다.
  - 녹화 재생은 `<video src="https://…/api/broadcasts/{n}/video">`다.
  - 라이브 시청은 웹뷰 JavaScript가 WHEP을 절대 주소로 부른다(CORS). 맥 웹뷰에서 WebRTC를 쓸 수 없으면 "웹에서 시청하기"를 보여 준다.
  - "웹에서 열기"는 OS 기본 브라우저로 방송 페이지를 연다.
  - 앱 이름은 "녹화방송", 번들 ID는 `com.haroobuzii.chzzk`다.
- **자동 검사·빌드·배포(GitHub Actions, main 푸시)**
  - **검사**: 기존 CI(fmt, 두 빌드, 테스트, README 개수, 비밀 키 검사)에 아래를 더한다.
    - Actions 설정 문법 검사(actionlint)
    - 셸 스크립트 검사(shellcheck)
    - 앱 기능 빌드 검사
  - **서버 배포**
    1. 검사가 통과하면 ARM64 러너에서 Dockerfile(short-url과 같은 cargo-chef·dx bundle 다단계)로 이미지를 만들어 GHCR(공개 패키지)에 올린다.
    2. SSH로 배포 서버에 들어가 compose로 새 이미지로 바꾼다.
    3. `/healthz`가 200이 될 때까지 기다린다(시간을 넘기면 실패).
    - GitHub Secrets: SSH 개인 키, 서버 주소, known_hosts.
  - **데스크톱 앱**: Windows x64(windows 러너, `dx bundle`로 MSI)와 macOS arm64·x64(macos 러너, `.app`/`.dmg`)를 만든다.
    - 맥 앱은 Developer ID로 서명·공증한다. 비밀 값이 아직 없으면 서명 없이 만들고 다운로드 페이지에 안내한다.
    - 결과물은 고정 태그 `app-latest`의 GitHub Release에 같은 파일 이름으로 덮어 올린다. 예: `chzzk-windows-x64.msi`, `chzzk-macos-arm64.dmg`, `chzzk-macos-x64.dmg`.
  - **iOS**: macos 러너에서 iOS 앱을 빌드·서명해 App Store Connect API 키로 TestFlight에 올린다.
    - Apple 승인과 비밀 값 등록 전에는 이 작업을 건너뛴다.
    - 외부 테스트 그룹과 공개 링크는 처음 한 번 App Store Connect에서 사용자와 함께 만든다.
- **비밀 값 위치**
  - 서버 `.env`: DB 비밀번호, 토스 테스트 키
  - GitHub Secrets: SSH 키, Apple 인증서·암호, App Store Connect API 키
  - 이 컴퓨터: `~/.oci`, `~/.ssh/chzzk_oci`

  저장소에는 자리표시자만 둔다. 키 확인은 `scripts/check-secrets.sh`로만 한다.
- **README**: 1~4단계 내용을 유지하고 아래를 더한다.
  - ⑥ 범위와 범위 밖
  - 공개 주소
  - 도메인과 비용
  - DNS·TLS 구성
  - OCI 리전·shape·OCPU·메모리·부트 볼륨과 선택 근거(재고·Pay As You Go·예산 알림·회수 조건)
  - 재현 절차(인프라 스크립트 → 서버 준비 → 비밀 값 → DNS → 첫 배포)
  - 자동 배포 흐름
  - 다운로드와 OS별 설치·실행 방법
  - 테스트한 OS·아키텍처와 결과 표
  - 리소스 정리 방법
  - 2단계 안내 수정: 배포 서버에서는 같은 와이파이가 아니어도 됨

## Testing Decisions

- 좋은 테스트는 외부 동작만 검증한다(지금까지와 같다).
- **서버(주 seam: HTTP 라우터)**
  - `/healthz`
    - DB 정상이면 200과 `db: "ok"`다.
    - MediaMTX에 닿지 않으면 200과 `mediamtx: "unreachable"`이다.
    - DB에 닿지 않으면 503이다(닫힌 풀로 흉내 낸다).
  - **CORS**
    - 앱 출처 `Origin`으로 보낸 목록·영상 GET과 WHEP 사전 요청(OPTIONS)·POST에 허용 헤더가 붙는다.
    - 같은 출처로 로그인·후원·댓글 같은 상태 변경을 보내면 지금처럼 403이다.
    - 쿠키 허용 헤더는 없다.
  - **다운로드 페이지**: 서버가 그린 HTML에 OS별 링크와 아키텍처 문구가 있다.
  - 1~4단계 테스트는 그대로 통과한다.
- **앱(seam: 서버 연결 모듈)**
  - 가짜 HTTP 서버(가짜 토스·가짜 MediaMTX와 같은 방식)에 목록·단건 JSON을 두고 확인한다.
    - 모듈이 목록을 읽는다.
    - 영상·WHEP·웹 주소를 서버 주소 기준으로 만든다.
    - 서버가 꺼져 있거나 500이면 연결 실패 문구를 돌려준다.
- **배포**
  - CI에서 actionlint와 shellcheck로 워크플로와 스크립트를 검사한다.
  - 운영용 compose 파일은 `docker compose config`로 문법을 검사한다.
  - 실제 배포는 사람이 확인하고 README에 기록한다.
    - 외부 네트워크(휴대폰 LTE 등)에서 HTTPS와 `/healthz`, 다운로드를 확인한다.
    - Windows PC·맥·아이폰에서 설치·실행, 목록, 재생을 확인한다.
- 화면 컴포넌트와 앱 창 자체는 자동 테스트하지 않는다.

## Out of Scope

- 안드로이드 앱. 배포가 끝난 뒤 원하면 무료 APK로 더한다.
- App Store 정식 출시. TestFlight 공개 링크까지만 한다.
- Windows 코드 서명(유료 인증서)
- 앱 안 로그인·댓글·후원. 웹에서 연다(ADR 0009).
- 여러 인스턴스, 오토스케일, 로드 밸런서(⑤에서 로컬로 한다)
- DB 백업 자동화, 모니터링·알림 서비스(상태 확인 주소까지만)
- CDN, Cloudflare 프록시(DNS only)
- 실제 결제(토스 라이브 키)
- 단축 URL 같은 다른 서비스를 하위 주소로 옮기는 일
