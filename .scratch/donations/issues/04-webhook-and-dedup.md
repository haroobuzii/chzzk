# 04: 승인 통지(웹훅)와 중복 방지

**What to build:** 토스의 승인 통지를 `POST /api/payments/toss-webhook`으로 받는다.

- 통지 본문은 믿지 않는다. 결제 키만 읽고, 결제 연결로 토스 조회 API를 불러 실제 결제를 가져온다.
- 가져온 결제를 02의 승인 확인 함수로 넘긴다.
  - `DONE`이면서 금액·주문 번호가 맞는 결제 대기 주문서는 확정한다.
  - `CANCELED`·`ABORTED`·`EXPIRED`면 결제 대기 주문서를 실패·취소·만료로 바꾼다.
- 언제나 빠르게 200을 준다. 모르는 결제 키나 꾸며낸 통지도 200으로 받고 아무것도 만들지 않는다.
- 쿠키·`Origin`이 없는 서버 간 요청이라 3단계의 CSRF 확인을 통과해야 한다. 통과하는지 테스트로 본다.
- 결과 화면(02)과 승인 통지 중 무엇이 먼저 오든, 몇 번 오든 주문서 하나는 한 번만 확정되고 후원은 하나만 생긴다.
