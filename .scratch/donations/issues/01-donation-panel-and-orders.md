# 01: 후원 칸과 주문서 (결제창 열기까지)

**What to build:** 다른 사람의 방송 상세 화면(녹화·라이브)에 **후원 칸**이 생긴다.

- **후원 칸 구성**
  - 금액 버튼 넷(1,000·5,000·10,000·50,000원), 직접 입력, 100자 메시지, "후원하기"
  - "테스트 결제 · 실제로 돈이 나가지 않아요" 표시
  - 후원 합계와 내역 자리. 아직 확정된 후원이 없으니 비어 있다
- **"후원하기"를 누르면**
  1. 서버가 **주문서**(결제 대기)를 만든다. 받는 사람은 방송 소유자, 금액은 서버가 검사한 값이다.
  2. 브라우저가 토스 v2 SDK로 **카드 결제창**을 연다. 돌아올 주소는 `/donations/success`와 `/donations/fail`이다.
- 결과 화면과 확정은 02에서 만든다.

**설정**

- `TOSS_CLIENT_KEY`와 `TOSS_SECRET_KEY`를 읽는다.
  - 둘 다 없으면 후원 기능이 꺼진 채로 켜진다. 후원 칸은 "토스 테스트 키가 필요해요"를 보여 주고, 주문서 API는 503이다.
  - 하나만 있거나 `test_`로 시작하지 않으면 서버가 켜지지 않는다.
- `TOSS_API_URL`과 `TOSS_TEST_FAIL_CODE`도 읽어 둔다(02에서 쓴다).
- `.env.example`에는 자리표시자만 둔다.

스펙의 "스키마", "후원 규칙", "주문서 저장소", 계약 `POST /api/broadcasts/{번호}/donations`, `GET /api/broadcasts/{번호}/donations`를 따른다. 주문서 표는 날짜·시각 이름 마이그레이션으로 만든다. 방송이 지워져도 주문서는 남기고 방송 번호만 비운다. 주문 번호는 추측할 수 없는 무작위 값, 6~64자 `[A-Za-z0-9_-]`다.

로그인이 안 됐으면 "로그인하고 후원하기", 소유자 없는 방송과 내 방송에는 후원 입력이 없다. 토스 사실 메모는 `docs/toss-payments.md`에 있다.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 주문서 만들기는 이렇게 응답한다. 결제 대기 주문서는 합계·내역에 나오지 않는다.
  - 비로그인 401, 없는 방송 404
  - 소유자 없는 방송 400(`no_owner`), 내 방송 400(`own_broadcast`)
  - 금액 위반(999, 500,100, 1,050) 400, 101자 메시지 400, 키가 없으면 503
  - 성공은 201과 `{order_id, amount, order_name, client_key}`
- [x] 주문서의 받는 사람은 방송 소유자이고, 금액은 서버가 받은 값이다(테스트로 확인)
- [x] `GET /api/broadcasts/{번호}/donations`는 누구나 부를 수 있고, 확정된 후원만 최신순으로 합계·건수와 함께 돌려준다(DB에 넣은 확정 행으로 테스트)
- [x] 설정은 이렇게 동작한다. `test_`가 아닌 키와 한쪽만 있는 키는 거절하고, 둘 다 없으면 후원을 끈다(단위 테스트)
- [x] 금액·메시지 규칙과 주문 번호 생성 단위 테스트(경계값, 형식, 서로 다름)
- [ ] 브라우저에서 후원 칸이 보이고, 로그인·소유자 조건에 따라 버튼이 바뀐다. 키가 없을 때 안내가 보인다. 테스트 키를 넣고 "후원하기"를 누르면 토스 결제창이 열리는 것은 키를 받은 뒤 사람이 확인한다
  - 에이전트 확인(가짜 키): 후원 칸, 비로그인·후원자·소유자·소유자 없는 방송 화면, 키 없을 때 안내, 주문서 생성까지 확인함. 진짜 결제창 열기는 키를 받은 뒤 사람이 확인한다.
