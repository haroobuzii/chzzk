# 02: 승인 확인과 후원 확정 (성공 흐름)

**What to build:** 결제 뒤 토스가 `/donations/success?paymentKey&orderId&amount`로 돌려보내면, 결과 화면이 `POST /api/donations/confirm`을 부른다. 서버의 **승인 확인**은 스펙의 "승인 확인" 순서를 따른다.

1. 주문서가 결제 대기인지 본다. 이미 확정이면 같은 결과를 돌려준다.
2. 돌아온 금액이 주문서와 다르면 토스를 부르지 않고 실패(`amount_mismatch`)로 바꾼다.
3. 토스 승인 API를 부른다. Basic 인증을 쓰고, `Idempotency-Key`는 주문 번호다.
4. 응답 상태가 `DONE`이고 금액·주문 번호가 같을 때만 "결제 대기일 때만" 조건부로 **확정**하고 결제 키를 남긴다.
5. 승인이 오류를 주면 주문 번호로 토스를 다시 조회해 실제 상태로 판단한다.

`TOSS_TEST_FAIL_CODE`가 있으면 승인 요청에 `TossPayments-Test-Code` 헤더를 붙인다.

- 결과 화면은 서버 응답만 믿고 "후원이 완료되었습니다", 방송, 금액, 돌아가는 링크, 테스트 결제 표시를 보여 준다.
- 방송 상세의 합계·내역에 확정된 후원이 나타나고, 라이브 방송 중이면 5초마다 갱신된다.

토스와 주고받는 코드는 **결제 연결** 모듈 하나에 모은다(ADR 0007). 나머지는 "승인됐다/아니다" 결과만 다룬다. 테스트용 **가짜 토스 서버**도 이때 만든다. 임의 포트의 작은 axum 서버로, 승인·조회 요청을 헤더까지 기록하고 테스트가 정한 대답을 돌려준다. `src/live/fake_mediamtx.rs`와 같은 방식이고 03·04가 함께 쓴다.
