# 02: 라이브 시작과 송출

**What to build:** 송출자가 `/live/new`에서 제목을 넣고 카메라 미리보기를 확인한다. 미리보기는 음소거, 후면 카메라 1280×720이다. "방송 시작"을 누르면 라이브 방송이 준비 상태로 생기고, 그 화면만 송출 키를 받는다. 영상은 WebRTC(WHIP)로 우리 서버를 거쳐 MediaMTX에 송출된다. 서버의 상태 감시기가 MediaMTX에 영상이 들어온 것을 보면 방송 상태가 방송 중이 되고 시작 시각이 기록된다. 송출 화면에는 빨간 LIVE 표시가 뜬다.

MediaMTX는 Docker Compose에 추가하고 설정 파일을 저장소에 둔다. 켜는 것은 WebRTC와 관리 API뿐이다. HTTP 포트는 127.0.0.1에만 열고, UDP는 와이파이로 연다. 추가 ICE 후보 주소에는 `LAN_IP`를 넘긴다. 자세한 계약은 스펙의 HTTP 계약(`POST /api/live`, `POST /api/live/{번호}/whip`과 세션 PATCH·DELETE), "MediaMTX 연결", "상태 감시기", "보안 경계"를 따른다. 상태 감시기는 2초마다 돌고, 서버가 켜질 때 한 번 바로 돈다. "한 번 맞추기"는 지금 시각을 받는 함수로 만든다. 이 티켓에서는 준비 → 방송 중 전환만 만든다. 나머지 전환은 04에서 만든다.

테스트용 가짜 MediaMTX도 여기서 만든다. 임의 포트에 띄운 작은 axum 서버로, 받은 요청을 기록하고, 정한 SDP answer와 `Location`을 돌려주고, 테스트가 정한 "지금 영상이 들어오는 경로" 목록을 돌려준다. 03·04·05 티켓도 이것을 쓴다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `docker compose up -d`로 DB와 MediaMTX가 함께 뜨고, MediaMTX의 HTTP 포트는 127.0.0.1에만 열린다
- [ ] `POST /api/live`에 맞는 제목을 보내면 201과 `{id, key}`가 오고, DB에는 키 원문이 아니라 해시만 있다. 제목 위반은 400이다
- [ ] 송출 연결은 이렇게 응답한다.
  - 키가 없거나 틀리면 401이고, 가짜 MediaMTX에 요청이 가지 않는다
  - 맞는 키면 answer와 우리 서버 주소로 바뀐 `Location`이 온다
  - 준비가 아닌 방송은 409, 없는 번호는 404다
  - 세션 PATCH·DELETE도 키를 확인한다
- [ ] 감시 한 번 맞추기: 경로에 영상이 들어오면 준비 → 방송 중이 되고 시작 시각이 생기며 목록에 나타난다
- [ ] 컴퓨터 브라우저(localhost)에서 실제 MediaMTX로 송출을 시작하면 방송 중이 되는 것을 직접 확인한다
- [ ] 1단계 테스트가 모두 통과한다
