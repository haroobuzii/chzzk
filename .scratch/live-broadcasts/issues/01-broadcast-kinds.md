# 01: 방송 종류 나누기 (준비 작업)

**What to build:** 방송이 녹화 방송과 라이브 방송 두 종류를 가질 수 있게 저장 구조와 화면을 넓힌다. 이 티켓에서 겉으로 보이는 기능 변화는 셋이다. 기존 방송은 모두 녹화 방송이 되어 목록 카드에 "녹화" 표시가 붙는다. 머리글 버튼이 "라이브 시작"(`/live/new`)과 "녹화 올리기"(`/new`)로 나뉜다. "라이브 시작" 화면은 아직 "준비 중" 안내만 보여 준다. 1단계 기능은 모두 그대로다. 스펙의 "스키마 변경"과 "상태 바꾸기" 결정을 따르는 마이그레이션을 이번에 넣는다. 종류, 방송 상태(준비·방송 중·종료·버려짐), 송출 키 해시, 시작·종료 시각 칸과, 종류에 맞는 칸만 채워지게 하는 `CHECK` 제약이 들어간다. 목록과 단건 조회는 종류, 방송 상태, 시작·종료 시각을 함께 돌려준다. 준비·버려짐 방송은 목록에서 빠지고, 단건 조회에서는 없는 방송이 된다.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 마이그레이션 뒤 기존 행은 녹화 방송이 되고, 1단계 테스트 32개가 수정 없이 통과한다
- [x] 라이브 방송에 영상 키가 있거나 녹화 방송에 방송 상태가 있으면, 그 행은 DB 제약으로 거절된다
- [x] 목록·단건 조회 결과에 종류, 방송 상태, 시작·종료 시각이 있다. 준비·버려짐 라이브 방송은 목록에 없고 단건 조회는 없음이다(DB에 직접 넣은 행으로 테스트)
- [x] 목록 카드에 "녹화" 표시가 붙는다
- [x] 머리글에 "라이브 시작"과 "녹화 올리기"가 휴대폰 폭에서도 한 줄로 놓인다. "라이브 시작"은 준비 중 안내 화면으로 간다
