# Spec: 2단계 휴대폰 라이브 송출과 시청

과제 원문(체크리스트 포함): `assignment.md`

Status: ready-for-agent

## Problem Statement

1단계 서비스에서는 미리 녹화한 영상만 올릴 수 있다. 지금 일어나는 일을 휴대폰으로 바로 보여 주고 싶어도 방법이 없다. 시청자도 "지금 누가 방송 중인지", "이 방송이 끝났는지"를 알 수 없다.

이 스펙은 "치지직 만들기" 과제 4단계 중 2단계다. 1단계(녹화 방송 등록·목록·상세·재생, `.scratch/recorded-broadcasts/spec.md`)를 그대로 유지하며 확장한다. 채점은 소스와 README만 읽는 정적 평가다. README에는 카메라·마이크 권한, 휴대폰 접속 환경, 송출 시작·종료 확인 방법이 반드시 있어야 한다.

## Solution

누구나 로그인 없이 휴대폰 브라우저에서 라이브 방송을 시작하고 종료한다. 동작은 아래와 같다.

- **송출**
  - 휴대폰은 카메라와 마이크 영상을 WebRTC로 미디어 서버 MediaMTX에 송출한다.
  - 우리 서버는 라이브 방송의 정보, 방송 상태, 송출 키만 관리한다(ADR 0004).
  - 방송을 시작한 화면만 송출 키를 받는다. 그 키가 있어야 송출과 종료를 할 수 있다(ADR 0005).
- **방송 상태**
  - 방송 상태는 준비 → 방송 중 → 종료 순서로만 바뀐다.
  - 송출이 끊기면 몇 초 안에 저절로 종료가 된다.
- **목록과 시청**
  - 목록 맨 위 "지금 라이브" 칸에 방송 중인 방송이 모이고, 그 아래에 녹화·라이브 방송이 함께 최신순으로 나온다.
  - 시청자는 같은 상세 화면 주소(`/broadcasts/번호`)에서 라이브 방송을 실시간으로 본다.
  - 방송이 끝나면 "방송이 종료되었습니다"를 본다.
- **실행 환경**
  - 내 컴퓨터에서 실행하고, 휴대폰은 Cloudflare 무료 터널의 HTTPS 주소로 접속한다.
  - 휴대폰과 컴퓨터는 같은 와이파이에 있어야 한다.

## User Stories

### 송출하는 사람

1. 송출자로서, 로그인 없이 휴대폰에서 라이브 방송을 시작하고 싶다. 계정 없이 지금 일어나는 일을 바로 보여 주기 위해서다.
2. 송출자로서, 머리글의 "라이브 시작" 버튼으로 송출 화면에 가고 싶다.
3. 송출자로서, 방송을 시작하기 전에 제목을 입력하고 싶다. 시청자가 어떤 방송인지 알 수 있게 하기 위해서다.
4. 송출자로서, 제목 규칙이 녹화 방송과 같기를 원한다. 앞뒤 공백을 지운 뒤 1~100자이고, 같은 제목도 된다.
5. 송출자로서, 제목이 규칙에 맞지 않으면 시작이 거절되고 이유를 보고 싶다.
6. 송출자로서, 송출 화면에 들어가면 브라우저가 카메라·마이크 권한을 묻기를 원한다.
7. 송출자로서, 방송을 시작하기 전에 카메라 미리보기를 보고 싶다. 화면 구도를 확인하기 위해서다.
8. 송출자로서, 미리보기에서 내 목소리가 스피커로 다시 나오지 않기를 원한다. 울림을 막기 위해서다.
9. 송출자로서, 기본으로 후면 카메라가 켜지기를 원한다.
10. 송출자로서, 전면·후면 카메라를 바꾸고 싶다. 방송 중에도 바꿀 수 있어야 한다.
11. 송출자로서, 카메라·마이크 권한을 거절했을 때 왜 시작할 수 없는지, 어떻게 허용하는지 안내를 보고 싶다.
12. 송출자로서, HTTPS가 아닌 주소로 들어왔을 때 터널의 HTTPS 주소로 접속하라는 안내를 보고 싶다.
13. 송출자로서, "방송 시작"을 누르면 송출이 시작되고 화면에 빨간 LIVE 표시가 뜨기를 원한다.
14. 송출자로서, 송출 연결 중에는 "연결하는 중…"을 보고, 시작 버튼이 다시 눌리지 않기를 원한다.
15. 송출자로서, 연결에 실패하면 이유를 보고 다시 시도하고 싶다. 같은 와이파이인지 확인하라는 안내도 받고 싶다.
16. 송출자로서, 방송 중에 내 방송의 상세 화면 링크를 보고 복사하고 싶다. 시청자에게 알려 주기 위해서다.
17. 송출자로서, "방송 종료"를 누르면 송출이 멈추고 방송이 종료되기를 원한다.
18. 송출자로서, 종료한 뒤 카메라와 마이크가 꺼지기를 원한다.
19. 송출자로서, 송출하는 동안 휴대폰 화면이 저절로 꺼지지 않기를 원한다.
20. 송출자로서, 화면 꺼짐 막기를 지원하지 않는 브라우저에서는 "송출 중에는 화면을 켜 두세요" 안내를 보고 싶다.
21. 송출자로서, 송출 화면을 닫거나 와이파이가 끊기면 방송이 저절로 종료되기를 원한다. 방송 중인 채로 목록에 남지 않게 하기 위해서다.
22. 송출자로서, 다른 사람이 내 방송을 끄거나 내 방송에 다른 영상을 보내지 못하기를 원한다.
23. 송출자로서, 송출 시작에 실패한 방송이 목록에 남지 않기를 원한다.

### 시청자

24. 시청자로서, 첫 화면 맨 위 "지금 라이브" 칸에서 방송 중인 방송을 보고 싶다.
25. 시청자로서, 방송 중인 라이브가 없으면 "지금 라이브" 칸이 보이지 않기를 원한다.
26. 시청자로서, 전체 목록의 카드마다 녹화·LIVE·종료 표시를 보고 싶다. 방송 종류와 상태를 한눈에 알기 위해서다.
27. 시청자로서, 방송 중 카드에서 시작 시각을 보고 싶다.
28. 시청자로서, 목록의 LIVE 표시가 새로고침 없이 갱신되기를 원한다.
29. 시청자로서, 라이브 카드를 누르면 상세 화면에서 바로 실시간 영상을 보고 싶다.
30. 시청자로서, 라이브 영상이 1초 안팎의 지연으로 보이기를 원한다.
31. 시청자로서, 브라우저가 소리 있는 자동 재생을 막을 때 "소리 켜기" 버튼으로 소리를 켜고 싶다.
32. 시청자로서, 컴퓨터 브라우저와 휴대폰 브라우저 모두에서 라이브를 시청하고 싶다.
33. 시청자로서, 보고 있던 방송이 끝나면 몇 초 안에 영상 자리에 "방송이 종료되었습니다"를 보고 싶다.
34. 시청자로서, 종료된 라이브 방송의 상세 화면에서 제목, 시작 시각, 방송한 시간을 보고 싶다.
35. 시청자로서, 종료된 라이브 방송은 다시 볼 수 없다는 것을 알고 싶다.
36. 시청자로서, 준비 중이거나 시작에 실패한 방송 주소를 열면 "방송을 찾을 수 없습니다"를 보고 싶다.
37. 시청자로서, 라이브 방송 링크도 녹화 방송과 같은 모양(`/broadcasts/번호`)이기를 원한다.

### 1단계 기능

38. 방문자로서, 머리글의 "녹화 올리기"로 1단계와 똑같이 녹화 방송을 등록하고 싶다.
39. 시청자로서, 녹화 방송의 목록·상세·재생·건너뛰기가 1단계와 똑같이 동작하기를 원한다.
40. 운영자로서, 1단계에서 저장한 녹화 방송이 2단계로 바꾼 뒤에도 그대로 조회되기를 원한다.

### 운영자와 채점자

41. 운영자로서, MediaMTX를 DB처럼 Docker Compose 명령 하나로 띄우고 싶다.
42. 운영자로서, 송출 연결과 상태 조회에 쓰이는 MediaMTX 주소를 환경변수로 바꾸고 싶다.
43. 운영자로서, 내 컴퓨터의 와이파이 IP를 환경변수 하나로 MediaMTX에 알려 주고 싶다. 휴대폰이 영상을 보낼 곳을 찾게 하기 위해서다.
44. 운영자로서, MediaMTX의 관리 API와 송출 연결 주소가 내 컴퓨터 밖으로 열리지 않기를 원한다. 송출 키 확인을 건너뛰지 못하게 하기 위해서다.
45. 운영자로서, 서버를 재시작해도 라이브 방송 기록(제목, 상태, 시작·종료 시각)이 남기를 원한다.
46. 운영자로서, 서버가 꺼진 동안 끝난 방송이 서버를 다시 켠 뒤 방송 중으로 남지 않기를 원한다.
47. 운영자로서, DB에 송출 키 원문이 저장되지 않기를 원한다.
48. 채점자로서, README에서 휴대폰 접속 환경(터널, 같은 와이파이), 카메라·마이크 권한 설정, 송출 시작·종료 확인 절차를 읽고 싶다.
49. 채점자로서, README에서 2단계 구현 범위와 범위 밖 항목, 새 환경변수 예시를 보고 싶다.
50. 채점자로서, 2단계 시점의 코드를 `step-2` 태그로 보고 싶다. 1단계 제출(`step-1`)은 그대로 남아야 한다.

## Implementation Decisions

- **용어**: GLOSSARY.md의 방송, 녹화 방송, 라이브 방송, 방송 상태(준비·방송 중·종료), 송출, 송출 키, 시청, 방송 번호를 쓴다. 준비 상태에서 끝내 방송 중이 되지 못한 방송은 "버려진" 방송이다. 저장소에는 따로 표시하지만 화면에는 보이지 않는다.
- **구성**:
  - 1단계와 같은 Dioxus fullstack 크레이트 하나를 쓴다(ADR 0003).
  - Docker Compose에 MediaMTX를 추가하고, 설정 파일을 저장소에 둔다.
  - MediaMTX에서는 WebRTC와 관리 API만 켜고 RTSP·RTMP·HLS·SRT는 끈다.
  - 포트는 아래처럼 연다.
    - WebRTC HTTP(WHIP/WHEP)와 관리 API: 내 컴퓨터 안(127.0.0.1)에만 연다.
    - WebRTC 영상용 UDP: 와이파이로 열어 휴대폰이 직접 영상을 보내게 한다.
  - 컴퓨터의 와이파이 IP는 MediaMTX 환경변수(추가 ICE 후보 주소)로 넘긴다. Docker 안에서는 컨테이너 IP만 보이기 때문이다.
- **스키마 변경**: 방송 표 하나에 칸을 더한다. 기존 행은 녹화 방송이 된다.
  - 방송 종류: 녹화 또는 라이브
  - 방송 상태: 준비·방송 중·종료·버려짐. 라이브만 가지며, 녹화 방송은 비어 있다.
  - 송출 키 해시: SHA-256. 라이브만 가진다.
  - 시작 시각, 종료 시각
  - 영상 키는 녹화 방송만 가진다.

  종류에 따라 반드시 있어야 하는 칸을 `CHECK` 제약으로 지킨다. 방송 번호는 녹화·라이브가 같은 번호 줄을 쓴다.
- **상태 바꾸기**:
  - 상태는 "지금 상태가 X일 때만 Y로" 바꾸는 조건부 UPDATE 하나로 바꾼다. 그래서 동시에 들어온 종료 요청과 감시가 부딪혀도 되돌아가는 일이 없다.
  - 바뀌는 길은 다음 넷뿐이다.
    - 준비 → 방송 중: 시작 시각 기록
    - 방송 중 → 종료: 종료 시각 기록
    - 준비 → 종료: 영상이 들어오기 전 종료 요청
    - 준비 → 버려짐: 30초 동안 영상이 없을 때
  - 준비 → 종료는 화면에 보이지 않게 버려짐으로 처리한다.
- **모듈**:
  - **라이브 방송 저장소**: 시작(제목 → 번호, 송출 키), 송출 키 확인, 상태 바꾸기, 목록·단건 조회에 종류와 상태 포함.
  - **송출 키**: 충분히 긴 무작위 값을 만들고 해시해 비교한다. 원문은 시작 응답에만 담긴다.
  - **MediaMTX 연결**: 설정된 주소로 WHIP/WHEP 요청을 넘기고, 관리 API로 지금 영상이 들어오는 경로 목록을 읽는다. 종료할 때는 송출 세션을 끊는다(실패해도 무시).
  - **상태 감시기**: 서버가 켜지면 2초마다 MediaMTX 경로 목록과 DB를 맞춘다. 한 번 맞추는 동작은 "지금 시각"을 받는 함수로 둔다. 테스트가 30초 경과를 흉내 내기 위해서다. 서버가 켜질 때 바로 한 번 맞추므로, 꺼진 동안 끝난 방송도 종료로 바뀐다.
  - **화면**: 머리글 버튼, 목록의 "지금 라이브" 칸과 표시, 상세 화면의 라이브 시청·종료 안내, 송출 화면.
- **MediaMTX 경로**: 라이브 방송 하나는 MediaMTX 경로 `live/<방송 번호>` 하나다.
- **HTTP 계약**: 새 라우트는 1단계 등록 API처럼 직접 덧붙인 axum 라우트다. 실패 응답은 1단계와 같은 `{code, message}` JSON이다.
  - `POST /api/live`
    - JSON `{title}`을 받는다.
    - 성공하면 201과 `{id, key}`를 준다. 이때 방송 상태는 준비다.
    - 제목이 규칙에 맞지 않으면 400이다.
  - `POST /api/live/{번호}/whip`
    - 송출 연결 요청이다. 헤더 `Authorization: Bearer <송출 키>`가 필요하다.
    - 키가 없거나 틀리면 401이고, MediaMTX에 넘기지 않는다.
    - 방송이 준비 상태가 아니면 409이고, 없는 번호는 404다.
    - 통과하면 SDP offer를 MediaMTX에 넘겨 answer(201)를 그대로 돌려준다.
    - `Location`은 우리 서버의 세션 주소로 바꾼다.
  - 위 세션 주소의 `PATCH`(ICE 후보)와 `DELETE`(연결 끊기)도 같은 송출 키를 확인한 뒤 넘긴다.
  - `POST /api/live/{번호}/whep`
    - 시청 연결 요청이다. 키가 필요 없다.
    - 방송 중일 때만 넘기고, 아니면 409, 없는 번호는 404다.
    - 세션 주소의 `PATCH`와 `DELETE`도 넘긴다.
  - `POST /api/live/{번호}/end`
    - 송출 키가 필요하다.
    - 성공하면 204와 함께 상태가 종료가 된다. 준비였다면 버려짐이 된다.
    - 키가 틀리면 401이다. 이미 종료된 방송이면 204이고 상태는 그대로다.
  - 기존 목록·단건 서버 함수는 종류, 상태, 시작·종료 시각을 함께 돌려준다. 준비·버려짐 방송은 목록에서 빠지고, 단건 조회에서는 없는 방송으로 취급한다.
- **화면**:
  - **머리글**: "라이브 시작"(`/live/new`)과 "녹화 올리기"(`/new`) 두 버튼을 둔다. 휴대폰 폭에서도 한 줄에 놓인다.
  - **목록 `/`**:
    - 방송 중인 방송이 있으면 맨 위에 "지금 라이브" 칸을 둔다.
    - 그 아래 전체 목록을 최신순으로 보여 준다. 정렬 기준은 녹화는 등록 시각, 라이브는 시작 시각이다.
    - 카드 표시와 시각은 아래와 같다.
      - 녹화: 녹화 표시와 등록 시각
      - 방송 중: 빨간 LIVE 표시와 시작 시각
      - 종료: 종료 표시와 시작 시각
    - 5초마다 서버 함수를 다시 불러 갱신한다.
  - **상세 `/broadcasts/{번호}`**:
    - 녹화 방송은 1단계와 같다.
    - 방송 중이면 WHEP으로 받은 영상을 `<video autoplay muted playsinline>`에 띄우고 "소리 켜기" 버튼을 둔다.
    - 5초마다 상태를 확인한다. 종료되면 연결을 닫고 "방송이 종료되었습니다"를 보여 준다.
    - 종료된 방송은 시작 시각과 방송한 시간(예: 12분 34초)을 보여 준다.
    - 준비·버려짐은 "방송을 찾을 수 없습니다"(404)다.
  - **송출 `/live/new`**:
    1. 제목을 입력한다.
    2. `getUserMedia`로 카메라 미리보기를 띄운다. 미리보기는 음소거하고, 후면 카메라 1280×720이 기본이다.
    3. 카메라 전환 버튼을 둔다. 방송 중에는 보내는 트랙을 바꿔 끼운다.
    4. "방송 시작"을 누르면 다음 순서로 진행한다.
       1. 시작 API를 부른다.
       2. RTCPeerConnection(sendonly)으로 offer를 만든다.
       3. ICE 후보 수집이 끝나면 WHIP으로 보낸다.
       4. LIVE를 표시하고 상세 화면 링크를 보여 준다.
    5. 송출 중에는 Screen Wake Lock을 건다.
    6. "방송 종료"를 누르면 종료 API를 부르고, 연결을 닫고, 카메라를 끈다.
    7. 화면을 떠날 때(pagehide)도 `keepalive` 요청으로 종료 API를 부른다.
  - 송출 키는 송출 화면의 메모리에만 둔다. 브라우저 저장소에 두지 않는다.
  - WebRTC와 카메라는 1단계 업로드처럼 `document::eval`로 실행한 JavaScript가 다룬다. 결과와 상태는 `dioxus.send`로 Rust 쪽에 알린다.
  - 권한 거절, HTTPS 아님, 연결 실패는 각각 한국어 안내로 보여 준다.
- **보안 경계**:
  - 휴대폰과 시청자는 우리 서버만 거쳐 MediaMTX에 닿는다. MediaMTX의 HTTP 포트는 내 컴퓨터 밖에 열리지 않는다. 그래서 송출 키 확인을 건너뛸 수 없다.
  - 시청에는 키가 없다.
- **설정(새 환경변수)**:
  - `MEDIAMTX_WEBRTC_URL`: 기본 `http://localhost:8889`
  - `MEDIAMTX_API_URL`: 기본 `http://localhost:9997`
  - `LAN_IP`: Docker Compose가 MediaMTX에 넘기는 컴퓨터 와이파이 IP

  `.env.example`에 예시를 둔다. 비밀 값은 없다.
- **실행 환경**:
  - 휴대폰은 `cloudflared tunnel --url http://localhost:8080`이 만든 `https://…trycloudflare.com` 주소로 접속한다.
  - 컴퓨터의 시청자는 `http://localhost:8080`을 쓴다. localhost는 보안 컨텍스트다.
  - 영상은 같은 와이파이 안에서 휴대폰과 MediaMTX가 UDP로 직접 주고받는다(ADR 0004).
- **README**: 1단계 내용을 유지하고, 아래를 더한다.
  - 2단계 구현 범위와 범위 밖 항목
  - 구성도(우리 서버, MediaMTX, 터널)
  - 새 환경변수와 와이파이 IP 찾는 법
  - `cloudflared` 설치와 터널 실행
  - 카메라·마이크 권한 허용 방법(iOS Safari, Android Chrome), 권한을 거절했을 때 다시 허용하는 법
  - 직접 확인 절차
    1. 휴대폰에서 송출 시작
    2. 컴퓨터의 "지금 라이브"에서 시청
    3. 카메라 전환
    4. 송출 종료 → 시청 화면과 목록에 종료 표시
    5. 송출 화면을 닫아 자동 종료
  - 테스트 결과
- **제출**: 같은 저장소에 이어 올리고 `step-2` 태그를 붙여 `tree/step-2`로 제출한다. 회고에서 만든 CI도 함께 올라간다.

## Testing Decisions

- 좋은 테스트는 외부 동작만 검증한다. 우리 서버에 HTTP 요청을 넣고 응답과 그 뒤의 조회 결과로 판단한다. SQL 문장, 해시 방식, 내부 함수 호출 순서는 검증하지 않는다.
- **주 seam: 서버 HTTP 라우터 전체** (1단계와 같다).
  - 테스트마다 `#[sqlx::test]` 임시 DB, 임시 보관 폴더, **가짜 MediaMTX**를 쓴다.
  - 가짜 MediaMTX는 임의 포트에 띄운 작은 axum 서버다. 하는 일은 셋이다.
    - 받은 WHIP/WHEP 요청을 기록한다.
    - 정해진 SDP answer와 `Location`을 돌려준다.
    - 경로 목록 API에서 "지금 영상이 들어오는 경로"를 테스트가 정한 대로 돌려준다.
  - 상태 감시기는 "한 번 맞추기" 함수를 테스트가 직접 부른다. 지금 시각도 넘겨 30초 경과를 흉내 낸다.
  - 검증 대상:
    - 라이브 시작:
      - 201과 번호·송출 키가 온다. 목록과 단건 조회에는 아직 없다.
      - 제목 위반은 400이다.
    - 송출 연결:
      - 키가 없거나 틀리면 401이고, 가짜 MediaMTX에 요청이 가지 않는다.
      - 맞는 키면 넘어가고 answer가 돌아온다. `Location`은 우리 서버 주소다.
      - 준비가 아닌 방송은 409, 없는 번호는 404다.
      - 세션의 PATCH와 DELETE도 키를 확인한다.
    - 감시:
      - 경로에 영상이 들어오면 방송 중이 되고, 시작 시각이 생기고, 목록에 나타난다.
      - 경로가 사라지면 종료가 되고 종료 시각이 생긴다.
      - 준비로 30초가 지나면 버려지고, 목록과 단건 조회에서 보이지 않는다. 30초 전에는 그대로다.
      - 종료된 방송은 경로가 다시 나타나도 방송 중이 되지 않는다.
    - 종료 요청:
      - 맞는 키면 204와 종료가 된다. 틀린 키면 401이고 상태는 그대로다.
      - 준비 중에 종료하면 버려진다.
      - 두 번 종료해도 204다.
    - 시청 연결: 방송 중일 때만 넘어가고, 준비·종료는 409다.
    - 재시작: 같은 DB에 새로 연결해도 라이브 방송의 상태와 시각이 그대로 조회된다.
    - 1단계 회귀:
      - 1단계 테스트 32개가 수정 없이 통과한다.
      - 녹화 방송과 라이브 방송이 섞여도 목록 정렬과 표시가 맞다.
- **보조**: 송출 키 단위 테스트. 서로 다른 키가 만들어지고, 맞는 키만 통과하는지 본다.
- 선행 사례는 1단계의 라우터 테스트(`oneshot` + `#[sqlx::test]` + 임시 폴더)와 재시작 테스트다.
- 진짜 카메라·WebRTC·MediaMTX를 거치는 송출과 시청은 자동 테스트하지 않는다. 대신 구현 중에 컴퓨터 브라우저로 송출·시청을 직접 확인한다(카메라 대신 가짜 장치나 화면 공유를 쓸 수 있다). 휴대폰 확인은 README 절차로 남긴다.

## Out of Scope

- 로그인·인가, 방송 소유자(3단계). 송출 키는 로그인이 아니다.
- 댓글(3단계), 도네이션(4단계)
- 라이브 다시 보기(녹화 저장), 썸네일, 시청자 수, 채팅
- LTE·5G 등 다른 네트워크에서의 송출과 TURN 서버
- 화질 선택, 송출 중 제목 바꾸기, 방송 수정·삭제(ADR 0002)
- 실제 서버 배포. 내 컴퓨터와 터널까지만 한다.
- 실시간 알림 장치(WebSocket). 5초마다 다시 묻는 방식으로 대신한다.

  - 0005: 송출 키
